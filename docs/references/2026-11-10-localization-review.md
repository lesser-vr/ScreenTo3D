# ScreenTo3D Localization 검토 — 2026-11-10

## 결론

한국어·영어부터 Qt 표준 번역 체계를 적용하는 것이 적합하다. Qt/QML이나
렌더러를 교체할 필요는 없지만, 문구 추출 전에 내부 상태와 표시 문자열을
분리해야 한다. 이 문서는 정적 코드 검토와 제안이며 제품 동작을 변경하지 않는다.

현재 앱 패키지에는 QML 14개와 Python 95개 파일이 있다. 그중 한국어가 포함된
파일은 QML 7개/83행, Python 26개/248행이다. 이는 한국어가 등장하는 행 수이며
고유 번역 항목 수나 사용자에게 실제로 노출되는 문구 수는 아니다. 네이티브
런처의 한국어 문구는 별도다.

앱 코드에서 `qsTr`, `qsTranslate`, `QTranslator`, `QLocale`, `retranslate` 사용과
앱 전용 `.ts`/`.qm` 카탈로그는 발견되지 않았다. 주 화면 외에도 모델 설명,
설치 진행, 오류창, 출력 메뉴·제목·오버레이, 런처 오류를 포함해야 한다.

## 권장 UX와 적용 범위

- 1차 언어는 **한국어 / English**. 기존 전역 설정 화면에 언어 선택 한 개를
  두고 기본값은 시스템 언어로 한다. 한국어 이외의 미지원 언어는 영어로 폴백한다.
  언어 선택은 기존 설정 저장소에 검증된 코드로 보관한다. 메인 화면의 창 선택과
  SBS 실행 흐름에는 추가 조작을 넣지 않는다.
- 화면 문구는 영어 원문과 한국어 번역을 기준으로 관리한다. 기술명
  `ScreenTo3D`, `DA2 Small`, `FP16`, `SBS`, `VFG`와 내부 모델·모드·형식 키는
  유지하고, 설명과 접근성 이름·도움말을 번역한다. 타 앱의 창 제목과 파일명,
  원본 라이선스·URL은 그대로 표시한다.
- 언어 변경은 GUI 스레드에서 문구와 표시 모델만 갱신하는 방식으로 설계한다.
  소스 선택, 파일 큐, SBS 출력 창/세션, VFG 상태를 재시작하거나 변경하지 않는다.
  진행 중 상태·오류창·메뉴·성능 제목도 갱신할 수 있도록 표시 전 상태를 보관한다.
- 오류는 현지화된 요약과 원래 진단 정보를 구분한다. 임의의 OS/라이브러리 예외를
  번역했다고 가정하지 않는다. 기존 Ctrl+C 복사는 오류 코드·원문 정보를 보존한다.
- RTL은 1차 언어 범위에 넣지 않는다. 향후 UI를 미러링하더라도 SBS 영상 자체,
  좌우/상하 눈 순서, 시차 부호는 변경하지 않아야 한다.

## 구현 방식 제안

1. 파일 상태와 캡처 단계 등 언어 독립 상태를 먼저 분리한다. GUI에 전달하는
   설치/작업 메시지도 `code + params`로 표현하고, 알려지지 않은 오류는 원문을
   진단 정보로 남긴다. GPU·캡처·추론 코드에 Qt 번역 의존성을 넣지 않는다.
2. QML은 `qsTr()`, Python UI 계층은 `QCoreApplication.translate()`와
   `QTranslator`를 사용한다. 문자열을 조각별로 번역해 붙이지 않고 인수를 가진
   완전한 문장을 카탈로그에서 관리한다. 영어 복수형을 사용하는 경우 영어
   numerus 카탈로그도 포함하거나 복수형 변화가 없는 표현을 사용한다.
3. 언어 관리자가 번역기를 교체하고 `QQmlEngine.retranslate()`와 Python 표시
   속성의 변경 알림을 함께 처리한다. QML 재번역만으로 이미 생성된 Python
   문자열과 Widgets 오류창이 모두 갱신되는 것은 아니다. VFG 안내 문구를
   재번역할 때에는 표시 타이머나 보간 전환 자체를 다시 시작하지 않는다.
4. 앱 번역뿐 아니라 Qt 표준 위젯 번역도 로드한다. 현재 준비 환경에는
   `qtbase_ko.qm`, `qtdeclarative_ko.qm` 등이 있다. Windows가 소유한 네이티브
   파일 선택 UI의 표준 버튼은 OS 언어를 따를 수 있으므로 앱 소유 제목·필터와
   구분한다. 런처는 Qt가 뜨기 전에도 한/영 오류를 표시할 수 있게 별도 처리한다.
5. `.ts` 추출과 `.qm` 생성 단계를 배포 빌드에 추가한다. 현재 배포기는
   `depthsbs_app`와 PySide6 폴더 전체를 복사하므로 패키지 내 번역 리소스를
   포함할 수 있지만, 카탈로그를 생성·검증하는 단계는 아직 없다. 신뢰된 동봉
   카탈로그만 읽고 미지원/손상된 선택에는 영어 폴백을 제공한다.

Qt 표준 체계를 사용하는 근거:
[Qt 6.10 문자열·인수·지역 형식 지침](https://doc.qt.io/qt-6.10/i18n-source-translation.html),
[QTranslator](https://doc.qt.io/qtforpython-6/PySide6/QtCore/QTranslator.html),
[QQmlEngine.retranslate](https://doc.qt.io/qt-6.10/qqmlengine.html#retranslate).

## 구현 후 확인할 항목

- 한국어·영어·시스템 자동·미지원 언어 폴백 및 선택 저장/재실행.
- 최소 창 크기, 125%/150%/200% DPI, 실제 번역과 길이를 늘린 시험 문구에서
  버튼·탭·선택 목록·도움말·상태 표시가 조작 가능한지 확인.
- 언어 변경 후에도 완료 파일 열기, 취소·중지 상태와 설치 오류 복사가 정상인지
  확인. 현재 한국어 라벨을 직접 단언하는 테스트는 상태/키 검사와 언어별 표시
  검사로 구분한다. 예: `test_desktop_gui.py:42`, `test_desktop_preferences.py:127`.
- 실행 중 언어 변경이 선택된 HWND/모니터 ID, 작업 큐, 출력 창, VFG 설정과
  기존 설정을 바꾸지 않는지 확인. 언어 갱신이 사용자 선택으로 저장되지 않게 한다.
- Full SBS/Half SBS/Top-and-Bottom의 양눈 안내와 성능 오버레이가 동일 언어로
  표시되고, 기존 압축축 보정·글꼴 크기·눈 순서를 유지하는지 확인.
- 소스 실행뿐 아니라 EXE 배포본에서 앱/Qt 카탈로그를 찾고 런처 실패도 원하는
  언어로 표시하는지 확인. 한글·공백이 있는 사용자 경로와 파일명도 포함한다.

이번 검토는 소스와 패키징 구조 확인이다. 실제 영어 번역, 번역 UI 실행,
글자 잘림 재현, 라이브 언어 전환 및 배포본 검증은 아직 수행하지 않았다.
