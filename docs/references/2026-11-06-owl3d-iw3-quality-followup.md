# Owl3D Live 3D / iw3 추가 적용 검토 — 2026-11-06

## 판단

다음 품질 실험은 **시차 곡선·예산 → 선택적 윤곽/가림 합성 → 출력 주기 비교**가
적합하다. 새 모델이나 더 강한 시간 평활화를 먼저 넣기보다, 동일한 현재 깊이를
어떻게 양안 영상으로 바꾸는지 분리해서 비교하는 편이 유용하다.

이 문서는 현재 코드·공식 자료·기존 설치 셰이더 증거에 대한 검토다. 새 모델 실행,
성능/화질 벤치마크, Owl3D 동시 A/B, 물리 표시 지연 측정은 하지 않았다. 앱 처리
코드·기본값·Owl3D 설정을 변경하지 않았고 commit/push도 하지 않았다. 아래 순위는
실험 제안이며 새로운 의무 순서나 제품 지원 선언이 아니다.

## 이미 반영된 부분과 남은 차이

GPU 캡처·전처리, FP16 추론, GPU 깊이/네이티브 출력, 최신 프레임 교체,
정상 캡처 생략 시 이력 유지, 깊이 범위 안정화, 모션 정렬 이력, 서브픽셀 및
부분 커버리지 합성은 이미 있다. 이들을 새 이식 후보로 중복 제안하지 않는다.
RowFlow symmetric도 별도 비교 경로가 준비되어 있으며, 사용자가 미룬 직접 시각
비교를 이번 검토가 자동으로 재개하지 않는다.

Owl3D 2.3.1 공식 설명은 Live 3D의 8비트 깊이 양자화 제거와 주 모니터가 아닌
Shift의 60Hz에 맞춘 표시를 구분해 소개한다. DepthSBS는 모델의 FP16 연산과 별개로
입출력·후처리 깊이를 float32로 유지하므로, 이 발표를 근거로 FP32 모델 추론으로
되돌릴 이유는 없다. 다만 표시 주기에는 비교할 여지가 있다.
[공식 Live 3D 설명](https://www.owl3d.com/blog/releasesv231)

Owl3D의 P05/P95 기반 시차 배율, 내용 가중 수렴점, 가장자리 양의 돌출 감쇠,
연속 가중 합성은 동일성이 재확인된 셰이더에 존재한다. 그러나 호스트의 시간
평활화, 활성 파라미터, Live 3D 모델 정체와 체감 차이의 원인 비중은 미확인이다.
관측된 budget 생산 셰이더는 두 방향에 같은 scale을 쓴다. 서로 다른 필드 이름만으로
독립적인 전경/배경 자동 예산이 이미 작동한다고 주장하지 않는다.

## 1. 비선형 시차 곡선과 압축 전용 예산 — 첫 실험 권장

**근거:** iw3의 mapper는 정규화 깊이를 그대로 선형 이동시키는 것 외에 여러
곡선으로 깊이→시차 관계를 조절한다. Owl3D 셰이더에는 깊이 분포를 사용한 배율과
제한 경로가 있다. DepthSBS의 현재 이동량은 `(depth - convergence) * scale / 2`다.
[iw3 mapper](https://github.com/nagadomi/nunif/blob/aa4d70984c8f75a1ed1597164cc6d6dd80bcae69/iw3/mapper.py),
[DepthSBS 투영 구현](../../experiments/cuda_projection/live_depth.cu)

**제안:** 수렴점과 강도 0.5를 유지하고, 화면면 부근의 시차는 유지하면서 큰 전경/
배경 시차만 부드럽게 압축하는 독립 GPU 후보를 만든다. 분포에 따라 입체감을
자동 증폭하는 기능은 첫 후보에 넣지 않는다. 전경/배경의 별도 상한은 우리 설계
제안이며, Owl3D의 확인된 활성 정책을 복제한다는 뜻이 아니다.

모션 이력 뒤, 좌우 투영 직전에만 적용하면 모델·시간 이력과 효과를 분리할 수 있다.
가장자리 가림 폭도 보정된 실제 이동량에서 계산해야 한다. pointwise CUDA 연산과
작은 통계 상태로 구현 가능해 새 모델 설치 없이 현재 Windows/RTX 경로에 맞는다.
성능 효과는 미측정이다.

**채택 기준:** 동일 RGB/깊이/강도에서 양안 시차의 P50/P95/최대값, 중앙 피사체,
전경/배경 깊이 순서, 시간별 시차 변화량을 비교한다. 중앙이 평평해지거나 예산이
움직여 화면 전체가 앞뒤로 펌핑하면 채택하지 않는다. 정상 범위에서는 기존 시차를
정확히 유지하는 구간을 두는 것이 좋다.

## 2. 선택적 윤곽 보정과 드러난 배경 합성 — 다음 품질 후보

**근거:** iw3에는 방향별 edge dilation과 DepthAA가 있다. Owl3D의 관측된 합성기는
여러 후보를 거리/깊이로 가중하고, 빈 영역에는 먼 쪽 이웃과 선형 샘플링을 쓴다.
DepthSBS는 현재 hard depth owner 이후 같은 깊이의 인접 다섯 후보를 재구성하고,
부분 커버리지에서 가까운 배경을 제한적으로 섞는다. 완전히 빈 영역은 먼 쪽 유효
픽셀의 색을 복제한다. 따라서 서브픽셀 개선을 했어도 소유자 전환·깊이 윤곽 오차·
가려진 배경의 색 늘어짐은 남을 수 있다. 이것은 현재 코드에서 추론한 후보이며,
사용자 장면의 주원인으로 측정된 것은 아니다.
[iw3 dilation](https://github.com/nagadomi/nunif/blob/aa4d70984c8f75a1ed1597164cc6d6dd80bcae69/iw3/dilation.py),
[DepthAA](https://github.com/nagadomi/nunif/blob/aa4d70984c8f75a1ed1597164cc6d6dd80bcae69/iw3/models/depth_aa.py),
[현재 hole resolver](../../experiments/cuda_projection/resolve_parallel.cuh)

**제안:** 두 후보를 따로 비교한다. (a) 깊이/RGB 경계가 일치하는 곳에만 아주 약한
수평 윤곽 보정, (b) 실제 구멍·부분 가림에서만 먼 표면의 연속 샘플링과 두 층
합성. 현재 guided filter 위에 모든 픽셀을 다시 평활화하거나, 전경 깊이를 넓게
팽창시키는 방식은 첫 후보에서 피한다. 상용 셰이더의 상수나 코드를 복사하지 않고
독립적으로 설계한다.

iw3 자체도 영상에는 foreground-scale 0을 권한다. 따라서 강한 foreground-scale을
그대로 가져오는 것이 아니라, 현재 기본의 극단적인 시차만 압축하는 새 비교
계약이 필요하다. DepthAA 역시 시간 안정화가 아닌 별도 학습형 공간 보정 모델이다.

**채택 기준:** 얇은 선·머리카락·철망·자막/HUD·좌우 이동에서 윤곽 두께, RGB 번짐,
가려진 배경의 늘어짐, 양안 비대칭을 측정한다. 정지 영상이 매끈해진 것만으로
채택하지 않는다. 새 DepthAA 가중치를 쓴다면 출처/허용 범위와 추가 비용을 따로
확인한다. 무거운 학습형 inpainting보다 작은 커널/단일 프레임 후보부터가 적합하다.

## 3. 출력 모니터에 맞춘 프레임 전달 비교 — 낮은 비용의 진단

DepthSBS의 30/60 옵션은 마지막 전달 시각에서 다음 deadline을 정하는 제한기다.
출력 디스플레이의 실제 위상과 동기화된 compositor pacing은 아니다. 네이티브 SBS
출력 FPS가 높아도 Owl3D가 받아 보는 프레임 간격이 균일하다고 보장할 수 없다.
[현재 전달 정책](../../v1/depthsbs_app/presentation_policy.py),
[Owl3D의 출력 주기 개선 설명](https://www.owl3d.com/blog/releasesv231)

먼저 기존 무제한/60 설정에서 같은 영상·같은 출력 모니터로 제출 간격 P95/P99,
프레임 반복/누락, 원본 나이와 VFG 원본/생성 비율을 비교한다. 차이가 확인되면
대상 모니터 기반 전달 타이밍을 검토한다. 사용자가 요청한 **무제한 기본값은
유지**하고, 단순히 60으로 강제 제한하는 것을 개선으로 간주하지 않는다.
물리 scanout/눈 추적은 우리 Qt 제출 통계와 별도다.

## 적용 범위·의존성

작은 CUDA 시차/윤곽 커널은 현 Windows/NVIDIA 구조에 넣을 수 있으며 Qt/QML UI나
모델 설치를 바꿀 필요가 없다. iw3 코드를 직접 재사용할 때는 MIT 고지를 보존하고,
외부 모델/가중치·라이브러리 조건은 따로 확인한다. 저장소 MIT가 모든 다운로드
가중치에 자동 적용되는 것은 아니다. Base의 기존 비상업적 가중치 조건도 유지된다.
Owl3D 코드·셰이더·모델을 제품에 복사하지 않는다.

우선 한 후보씩 현재 `window` 경로와 비교하고, 출력 형상·좌우 방향·새 영역/컷·
GUI lifecycle 검증과 물리 Owl3D 시청을 분리해서 기록한다. 사용자에게 새 고급
옵션을 늘리는 것은 이 검토의 권장이 아니다.
