# oVDA 모델 특성과 ScreenTo3D 튜닝 검토

2026-11-09. 논문·공식 코드와 현재 앱을 대조한 연구 검토다. 이번 검토로
런타임이나 기본값을 변경하지 않았다. 아래 후보의 화질·성능 향상은 아직
실험으로 확정하지 않았다.

## 가장 큰 불일치: 이력의 수명이 너무 짧다

현재 `live_sbs.reset_reason()`은 oVDA에서 캡처 인덱스가 한 번이라도
건너뛰면 `gap`을 반환한다. 그때 모델 캐시와 렌더러 이력이 함께 초기화된다.
oVDA는 stateful/requires-every-frame이고, 어댑터의 coalesced_history는 false다.
따라서 기존 DA2의 100ms 이력 유지 규칙이 적용되지 않는다.

최근 실제 GPU 캡처 벤치마크의 **after 조건**을 다시 집계했다.
각 크기는 6개 구간, 약 18초 분량이다. 새 캡처/추론은 실행하지 않았다.

| 입력 | 추론 업데이트 | 초기화 횟수 | 업데이트/초기화 비율 |
|---|---:|---:|---:|
| 1920×1080 | 1,082 | 43 | 25.16 |
| 3840×2160 | 846 | 279 | 3.03 |

자료: `out/ovda-runtime-cleanup-20261109/native-final/report.json`.
초기화 카운터는 원인별 구분을 포함하지 않으며, 위 비율로 실제 캐시 점유율이나
최장 연속 이력 길이를 복원할 수는 없다. 하지만 4K에서 이력을 자주 잃는다는
점은 분명하고, 캡처 누락마다 초기화하는 코드와 함께 우선 조사할 근거가 된다.

논문 §3.3은 일정 간격으로 1~4번째 프레임을 샘플링해 학습한다고 설명한다.
부록 A.2의 가상 이력 실험 역시 각 캐시 안의 시간 간격을 일정하게 유지한다.
따라서 캡처 인덱스의 연속성과 모델 입력 시퀀스의 연속성을 분리해 보는 것이
타당하다. 이는 무제한·불규칙 누락 허용의 증거는 아니다.

**첫 실험 후보**는 짧은 단발 누락에서 캐시를 유지하는 정책이다. 입력
타임스탬프의 전진, 누락 개수·시간 간격의 상한을 검사하고, 장면 전환·입력
변경·리사이즈·긴 정지·시간 역전에서는 계속 초기화하는 비교가 적절하다.
실제 시간과 현재 처리율을 함께 기록해 초기화 사유, 사용 중인 캐시 길이,
연속 업데이트 길이의 분포를 수집해야 한다. 복제 프레임을 캐시에 채우거나
캡처 번호를 그대로 절대 위치 인덱스에 넣는 방식은 현재 학습/캐시 규약과 다르다.

그다음 후보는 일정한 모델 샘플링 간격이다. 예를 들어 4K에서 60Hz 입력을
불규칙하게 약 47회 처리하는 경우와, 30Hz 모델 업데이트를 비교할 수 있다.
이것은 자동 품질 향상이나 출력 60FPS 유지가 보장되는 설정은 아니다.
원본 RGB·깊이·출력 시간을 분리하고, 다른 시각의 깊이를 쓰는 프레임에는
정렬/재투영과 가려짐 처리까지 별도로 검증해야 한다. 현재 앱의 매 처리
프레임 추론 계약을 바꾸는 실험이며 단순 FPS 제한과 동일하지 않다.

## 후처리 선택을 모델의 이력 정책에서 분리할 여지

`live_sbs.py`는 `model.coalesced_history`가 true인 경우에만
`projection.configure_live_quality()`를 호출한다. oVDA는 false이므로 최근
DA2용 시간 기반 범위 응답·입체 출력 보정이 활성화되지 않는다. 반면 기존
Video Quality 정책의 EMA alpha=0.18, 가이드 반경 12는 적용된다.

현재 CUDA 경로는 P2–P98 깊이 범위를 프레임마다 계산하고 EMA로 갱신한다.
oVDA에서는 시간 기반 범위 갱신이 비활성화돼 있다. 이후 움직임/깊이 차이
조건을 통과한 픽셀에 추가 깊이 EMA를 적용한다.

다음 비교가 유용하다.

1. 캐시 누락 정책과 렌더러 기능 선택을 분리하고, oVDA용 후처리 조합을
   독립적으로 선택한다. DA2용 기능을 모두 한꺼번에 켜는 비교는 피한다.
2. 이력 정책을 고정한 상태에서 추가 깊이 EMA의 alpha를
   0.18 / 0.5 / 0.75 / 1.0으로 비교한다. alpha=1은 이 EMA를 우회하는 대조군이다.
   현 상태의 EMA가 계속 적용되는 픽셀이라면 가중 평균 이력 지연은 약
   4.56프레임이지만, 움직임 게이트가 우회하는 곳에는 해당하지 않는다.
   이는 앱 전체 지연 측정치가 아니다.
3. 렌더링용 깊이 범위를 장면 시작 후 안정적으로 추정하고, 느린 확장·회복을
   허용하는 방식과 현재 적응 범위를 비교한다. 과거 프레임만 사용하며,
   원거리/근거리 새 물체가 들어왔을 때 잘림과 입체 시차 안전 범위를 확인한다.
   첫 프레임 범위를 무조건 영구 고정하는 방식은 부적절하다.
4. 필요하면 가이드 반경 12와 8을 별도 비교한다. 모델 자체의 경계와 UI/얇은
   물체를 지키는지를 우선 보며, 기존 radius-12 CUDA 최적화는 이미 적용돼 있다.

모델의 scale/shift 안정성 학습과 앱의 시차 매핑은 다른 문제다.
SaSCon은 학습에 이미 들어간 손실이므로 추론 옵션으로 덧붙일 대상이 아니다.
학습된 안정성을 화면별 재정규화나 중복 평활화가 얼마나 바꾸는지 분리해서
평가하는 것이 먼저다. 빠른 물체의 잔상과 긴 영상의 scale drift는 저자도
[한계로 명시한다](https://arxiv.org/html/2510.09182v1#S6).

## 해상도·정밀도·캐시 크기

| 후보 | 프로젝트에 맞는 검토 방향 |
|---|---|
| 낮은 추론 해상도 | 현재 518×924와 392×700을 우선 비교. 모델 입력 픽셀은 약 42.7% 줄지만, 원본·눈별 출력 해상도는 유지한다. 14 배수 프로파일, 종횡비 보존, 패딩 제거, 캐시 형태와 새 엔진 검증이 필요하다. |
| FP16 재평가 | 기존 encoder+spatial 혼합 FP16 후보를 GPU 캡처와 충분히 채워진 이력에서 다시 비교. 이후 전체 FP16/캐시 FP16은 별도 후보. 현재 FP32 기본값 변경은 제안 단계다. |
| c8 | 우선순위 낮음. 논문 부록의 43 대 42FPS 차이와 기존 로컬의 혼합/악화된 시간축 경계 결과를 함께 보면, c16 이력을 먼저 제대로 활용하는 편이 합리적이다. |
| 더 긴/여러 캐시 | 우선순위 낮음. 논문 A.2의 교대 캐시는 독립적인 scale/shift drift 문제를 보였으며, 정식 긴 이력 모델과 동일하지 않다. |

논문의 대표 42FPS는 280×924 추론 조건이며 1080p/4K SBS 전체 경로 수치가
아니다. 16:9 화면을 280×924로 찌그러뜨려 맞출 이유도 없다.
해상도 축소는 모델과 캐시에만 영향을 주므로 4K 렌더러 비용 감소율은 별개다.

FP16의 논문 평가는 KITTI 정확도 기준이다. 앱의 FP32 대비 엄격한 수치
동일성 실패와 실제 품질 저하는 구분해야 한다. 기존
[동기화된 정밀도 비교](../evidence/ovda-precision-aspect-20261109.md)는 평균
차이가 작았지만 시각적 편안함을 판정하지 않았다. 안정된 이력 상태에서
장시간 누적 오차·잔상·시차 변화와 실제 출력 성능을 새 기준으로 평가할 여지가 있다.

또한 현재 캐시는 완성된 K/V를 그대로 저장하는 LLM 캐시와 다르다.
공식 `dpt_temporal.py`는 특징에 위치 인코딩을 다시 더한 뒤 K/V 선형층을
계산한다. 출력 K/V를 무조건 재사용하거나 xFormers 설치만으로 현재 TensorRT
경로를 가속할 수 있다는 가정은 맞지 않는다.

## 제안하는 검증 순서

1. 기존 경로에 캐시 사용 길이·초기화 사유·실제 입력 간격을 계측한 뒤,
   제한적인 단발 누락 허용을 비교한다.
2. 같은 입력 시퀀스와 이력 상태에서 EMA와 깊이 범위 매핑을 각각 비교한다.
3. 이력이 충분히 유지되는 조건을 확정한 뒤 해상도와 FP16을 비교한다.

짧은 추론 FPS 외에 고정 표면의 시차 흔들림, 움직이는 경계의 지연/잔상,
가려짐·컷 직후의 회복, 얇은 물체·텍스트 손실, 장시간 스케일 변화와 실제
네이티브 출력률을 함께 본다. 공개 영상의 GT 없는 지표는 비교용 대리 지표이며,
실제 깊이 정확도를 주장하려면 별도의 정답 깊이 자료가 필요하다. 이번 검토는
새 모델 실행·튜닝 구현·시각적 수용성 확인을 대신하지 않는다.
