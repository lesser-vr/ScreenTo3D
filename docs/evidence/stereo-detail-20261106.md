# 입체감 0.25와 선택적 윤곽·배경 채움 — 2026-11-06

## 적용 범위

사용자 요청에 따라 live 기본값과 기본값 버튼을 0.25로 변경했다. 일반 앱과
Base/Small 비교 실행기가 같은 상수를 사용한다. 기존 무제한 출력 기본은 유지한다.
파일 변환의 강도는 변경하지 않는다.

별도로 [Owl3D/iw3 후속 검토](../references/2026-11-06-owl3d-iw3-quality-followup.md)의
2번을 작은 GPU 보정으로 구현했다. 준비된 로컬 Small/Base 라이브 기본은
`detail`이며 기존 `budget`은 진단 비교용으로 남는다. 두 비교 출력 모두 같은
0.25로 맞추었으므로 아래 차이는 강도를 내린 효과와 분리된다. 외부 코드·가중치를
복사하거나 새 모델을 설치하지 않았다. 물리 Owl3D 시청 평가는 하지 않았다.

## 설계와 제한

`experiments/cuda_projection/stereo_detail.cuh`에서 두 기능을 독립적으로 켜고
검사한다. 플래그 0은 기존 budget, 1은 윤곽, 2는 채움, 3은 둘 다다.

**윤곽:** 좌우 두 픽셀씩을 보고, 안정된 두 깊이 면 사이의 중간 깊이 픽셀이
한쪽 RGB와 일치하고 반대쪽과 뚜렷이 다를 때만 그 면 쪽으로 미세 보정한다.
깊이 환산 최대 변화는 0.025이고 RGB·깊이·평탄도·경계 위치의 신뢰도를 연속적으로
곱한다. 보정 결과는 기존 guided-filter scratch `t0`에 기록하며, 모델 결과와
시간 이력 `aligned`는 수정하지 않는다. 별도 전체 프레임 버퍼나 새 시간 상태는 없다.

최종 이동량은 원래 floor/ceil 구간 안으로 다시 제한한다. 원래 정수 이동은
정확히 유지한다. 따라서 윤곽 보정은 기존 splat 목적 픽셀, 가시성 승자와 구멍
위치를 바꾸지 않는다. 표면 우선순위·동일 면 구분·배경 판정에도 원래 깊이를 쓴다.
진단용 corrected-depth snapshot은 이 최종 이동 제한 전의 제안값이다.
1~2픽셀짜리 선명한 물체, 정상 깊이 경계와 평면은 보정 조건에 들어가지 않는다.

**배경 채움:** 이미 덮인 부분은 기존 subpixel 합성을 유지한다. 부분적으로 덮인
전경 픽셀과 실제 빈 픽셀에서만 더 먼 면을 선택한다. 빈 픽셀은 양쪽 최대 32픽셀
내 가시 표본과 실제 깊이 차이가 있어야 한다. 화면 끝의 일방향 빈 구간은 유지한다.
역투영 위치의 두 표본이 같은 배경 면이면 선형 보간한다. 실제로 가려져 있으면
같은 면의 이웃 세 개로 일정한 색 변화율을 확인하고 최대 4 원본 픽셀만 연장한다.
큰 기울기·휘어진 색 변화·다른 깊이·거리 한계에서는 적용량이 부드럽게 줄어든다.
불확실하면 기존 채움을 유지한다. 복잡한 무늬나 넓은 비가시 영역을 복원하는
생성형 inpainting은 아니다.

두 기능은 화면 가림 전에 실행된다. VFG는 동일한 보정 원본을 보간하고 기존
생성 후 가장자리 보호를 유지한다. 파일/reference, RowFlow, VDA/oVDA에는 적용하지
않는다. 사용자 옵션은 추가하지 않았다. 정상 경로에는 readback/추가 동기화가 없다.

## 수정 과정에서 발견한 문제

첫 후보는 보정 깊이를 표면 구분에도 사용했다. 공개 Base 영상의 작은 깊이 변화가
기존 0.01 표면 구분 경계를 넘으며 윤곽 보정 단독 최대 RGB 차이 125/127/138을
만들었다. `base-public.json`은 이 후보의 관측 기록이지 채택 근거가 아니다.
표면 구분을 원래 깊이로 고정한 v2에서는 Base가 19/32/25로 줄었지만 Small의
한 장면에 68이 남았다. 최종 v3는 원래 splat 구간까지 보존해 불연속적인 가시성
승자 전환을 막는다. v1/v2의 비용·수치와 최종 v3 검증을 섞지 않는다.
최종 v3의 윤곽 보정 단독 최대 RGB 차이는 Base 13/11/25, Small 13/12/9다.
이는 시간별 flicker 오차가 아니라 같은 프레임의 보정 전후 차이이다.

## 합성 정답 검증

`v1/check_stereo_detail.py`, `out/stereo-detail-20261106/synthetic-v3.json`.
알려진 두 깊이 면, 전경 폭 1/2/8/96픽셀, 강도 0.25/0.5/1, 각각 연속 21개
위상 조건에서 양안을 비교했다. 배경의 원래 색 변화와 전경 alpha로 독립 정답을
계산한다. 윤곽·채움을 각각 켜고 둘 다 켠 결과를 분리한다.

| 전경 폭 | 강도 0.25 문제 영역 RGB MAE 기존→채움 | 감소 |
|---|---:|---:|
| 1px | 0.34149→0.28712 | 15.9% |
| 2px | 0.35374→0.29828 | 15.7% |
| 8px | 0.34143→0.31591 | 7.5% |
| 96px | 0.10620→0.09842 | 7.3% |

RGB 단위는 0..255다. 이 표는 배경 채움 정답 오차이며 실제 영상의 화질 개선률이
아니다. 0.25에서는 시간별 정답 오차 변화도 네 경우 모두 작아졌다. 다른 강도의
일부 경우에는 양자화에 따른 아주 작은 증가가 남아 있어 전 범위 시간 개선을
주장하지 않는다. 합성 검사는 전경 완전 불투명 픽셀 exact, 얇은 선의 깊이 exact,
색 경계 없는 불확실 깊이의 보정 생략, 보정 상한, 플래그 독립성과 잘못된 값
거부도 검사한다. 불확실 깊이 fringe의 보정 방향이 정답 면으로 향함을 확인했다.

추가 16×16, 64×32, 1920×1080, 3440×1440, 1080×1920, 3840×2160,
4096×2160에서 꺼진 경로가 기존 budget DLL과 exact, 최종 host/native RGBA
exact, textured 평면 exact를 확인했다. 실제 GPU shift의 floor/ceil이 윤곽 보정
전후 동일함도 검사했다. 합성 검사 통과는 일반 장면의 시각 수용을 대신하지 않는다.

## 공개 영상과 관측 범위

FloorballGame / OfficeWalk / ParkingGarage 각 90 연속 프레임, Base/Small 각각
270프레임, 1920×1080, source clock 60Hz, 강도 0.25. 현재 범위 안정화와 모션
이력을 거친 **동일 깊이**에 네 플래그를 적용한다. 프레임 0/45와 감지 컷에서
이력을 초기화한다. 원본 깊이가 투영 전후 exact임을 매 프레임 확인한다.
출처·이용 조건은 결과 JSON의 `attribution`을 따른다. 개인 화면은 저장하지 않았다.

`base-public-v3.json`, `small-public-v3.json`이 최종 결과다. `*-changes.png`는
왼쪽 눈에서 변화가 큰 320×180 영역을 원본/budget/윤곽/채움/전체로 비교한
정지화면이다. 이는 자연 영상의 정답이나 정상 속도 재생·양안 시청 검증이 아니다.

낮은 기본 강도에서는 적용 구간이 매우 작다. 전체 화면의 일렁임 해결을 주장하지 않는다.
