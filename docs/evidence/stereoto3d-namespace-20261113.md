# StereoTo3D 내부 이름 전환 검증

2026-11-13. 사용자가 승인한 권장안의 로컬 구현 결과다. 앱 표시명·EXE·저장소와
릴리스 파일명은 ScreenTo3D로 유지했다. 기존 체크아웃 경로는 변경하지 않았다.
이번 작업은 커밋·push·GitHub 릴리스 교체를 수행하지 않았다.

## 변경 범위

- 정식 Python 구현은 `v1/stereoto3d_app/`이다. 소스 import, Qt 작업자·설치 작업자
  진입점, 패키징·측정·테스트 스크립트도 같은 이름으로 연결했다.
- 내부 번들 경로는 `out/gpu-preview/StereoTo3D-GPU-Preview/_internal`이다.
  개발 SDK·모델 원본은 재다운로드하지 않고 기존 자원을 보존한 채 새 경로에
  하드링크로 준비했다. 최종 포터블은 일반 파일로 복사되어 이 개발 경로에 의존하지 않는다.
- C++ 네임스페이스·헤더 디렉터리·CMake 대상과 CLI는 `stereoto3d` 이름을 쓴다.
  아이콘 파일명과 현재 문서·안내·임시 파일·스레드 이름도 정리했다.
- 모델·런타임·다운로드·Small 엔진·실행 로그의 공통 루트는 앞서 적용한
  `%LOCALAPPDATA%\StereoTo3D`를 그대로 사용한다. Qt 내부 application/organization
  이름도 바뀌어 화면 캐시가 `StereoTo3D\StereoTo3D\cache` 아래에 생성된다.
- `StereoTo3D.Native` 등록을 위해 Qt 출력 DLL을 재빌드하고 승인 해시를 갱신했다.
  새 SHA-256은 `6a17a5b14ef3ea92ac09c39e2124efaae2401682524d5a317fbd37644816e985`다.
  모델 그래프·엔진 정밀도·렌더링 알고리즘은 변경하지 않았다.

## 호환 처리

| 대상 | 동작 |
|---|---|
| 설정 | `StereoTo3D/StereoTo3D`에 없는 언어·실시간/파일 모델·모드·출력 형식만 기존 `DepthSBS/DepthSBS`에서 가져온다. 새 값을 덮어쓰지 않고 옛 저장소를 보존한다. 경로 등 소유하지 않은 키는 옮기지 않는다. 오류는 `E_SETTINGS_MIGRATION`으로 처리한다. |
| 네이티브 실행기 언어 | 새 레지스트리 값을 우선한다. 값이 없을 때만 이전 저장소를 읽으며, 새 `system` 선택을 이전 언어로 덮지 않는다. |
| 환경변수 | `STEREOTO3D_*`가 우선하며 없을 때 `DEPTHSBS_*`를 동적으로 읽는다. 빈 새 값도 명시적 선택이며, 이전 값을 환경변수에 복제하지 않는다. 실험용 네이티브 실행기의 관련 옵션도 이전 이름을 읽는다. |
| 이전 실행 명령 | 옛 Python 스크립트와 `depthsbs_app.launcher`, `.main`, `.desktop`는 새 구현을 호출하는 작은 호환 진입점이다. 이전 내부 모듈 전체를 중복 로드하지 않는다. 임의의 옛 라이브러리 import 경로 전체를 지원하는 API 호환 패키지는 아니다. |
| 출력 재캡처 방지 | 새 출력에 `StereoTo3D.OutputWindow.v1`과 `DepthSBS.OutputWindow.v1`을 함께 기록한다. 새 앱은 어느 표시든 출력으로 판정하므로 이전/새 버전 사이의 재캡처를 막는다. 외부 프로세스의 창에 표시를 쓰지 않는다. |
| QML 모듈 | 새 DLL이 `StereoTo3D.Native`와 이전 `DepthSBS.Native`를 등록한다. 두 이름으로 실제 픽셀 전달을 검증했다. |
| C++ 도구 | 새 CLI 빌드가 기존 `depthsbs` 명령 별칭도 만든다. 옛 경고 옵션과 SDK 경로 CMake 변수는 새 값이 없을 때만 채택한다. SDK 스모크 도구 자체의 전체 GPU 검증을 새로 수행한 것은 아니다. |

현재 코드·문서의 옛 이름 검색 결과는 호환 코드·이관 상수·시험 fixture·이관
설명으로 한정됐다. 이 검증 문서 작성 전 스냅샷은 허용된 31개 참조 행을 기록했다.
과거 증거·릴리스·날짜별 검토 문서 137개는 작업 전과 바이트가 같고,
승인된 PNG 그림과 모델 그래프 핀·모델 배포 원본도 변하지 않았다.
무시된 옛 빌드·사용자 데이터 안의 과거 캐시는 삭제하거나 일괄 치환하지 않았다.

## 검증

- CPU/Qt 계약 **550개** 통과. 이 중 새 이름 이관 검사는 10개다. 최종 호환
  진입점 추가 후 Qt 그룹 **66개**를 다시 통과했다.
- C++ 코어를 새 빌드 폴더에서 빌드하고 CTest, 새 capability 명령과 옛 mode
  명령 별칭을 확인했다. 최초 기존 빌드 폴더는 사라진 컴파일러 경로가 캐시에
  남아 실패했으며, 설치된 MSVC 2022의 새 폴더로 검증했다.
- 새/옛 QML 이름 각각 실제 GPU 두 창의 정확한 픽셀·프레임 ID, 숨김/복원,
  크기 변경, clear/stop과 노드·풀 해제 검사를 통과했다.
- 출력 표면이 있는 Qt 창과 텍스트 전용 창을 30회 비교했고 글자 영역의
  픽셀 차이는 모두 0이었다. 121개 바이너리의 Qt 정적/지연 의존성도 통과했다.
- 새 포터블에서 생성한 창만 캡처해 Small·Base·VDA의 Half Top-and-Bottom
  출력을 확인했다. 각 모델에서 실제 출력 프레임, 양쪽 Win32 표시와 정상 중지를
  확인했다. 초기 직접 호출 시험은 설치 런타임 연결 단계를 빠뜨려 Base에서
  실패했으며, 실제 사용자 시작 경로와 같은 런타임 연결 후 세 모델이 통과했다.
- 새 GUI에서 Small·Base·VDA 320×180 및 VDA 320×192를 각 12프레임 변환했다.
  출력 크기·프레임 수·오디오·전체 디코드가 통과했다. 기존 검증된 QA FFmpeg를
  명시해 추가 미디어 설치는 하지 않았다.
- 실제 설정 검증에서 옛 저장소와 이미 있던 새 값이 유지됐다. 실제 모델·엔진·
  다운로드 캐시 45개 / 3,240,056,869바이트는 이전 해시와 같았다. 재다운로드나
  엔진 재생성 없이 기존 Base·VDA를 인식했다. 새 Qt 캐시 디렉터리 생성도 확인했다.
- 새 포터블·저장소 루트 EXE·이전 네이티브 실행기와 최종 ZIP 추출본을
  Windows 기본 PATH에서 실행하고 정상 종료했다. 이전 실행기는 실제 옛
  모듈명·로그 환경변수를 통해 새 구현을 열었다.

이는 이름 전환·호환·출력 동작 검증이며, 새로운 성능 향상이나 물리 3D 화질
승인을 주장하지 않는다. 세부 결과는 `out/rename-20261113/`의 JSON·로그에 있다.
작업 전 소스와 기존 변경사항은 같은 폴더의 `before.zip`에 보존했다.
