후속 결정(2026-11-13): 사용자가 커밋 이메일의 공개를 허용하고 유지를 요청했다.
따라서 아래 이메일 항목은 정리 대상에서 제외한다. 문서 경로·앱 캐시와 Git 이력의

앱 ZIP의 Python 캐시에 남은 사용자 경로를 확인했다. 모두 아래에 원문을 가려 기록했다.
이메일은 인증 비밀이 아니며, 공개 의도는 확인되지 않았다.

`oma-qa`의 후보 수집·수동 검증 절차에 로컬 패턴 검색을 조합했다.
전용 Deepsec/Gitleaks 등의 보안 엔진은 실행하지 않았다. 외부 AI 분석 서비스에
소스나 후보를 전송하지 않았다. 검토 깊이는 **partial**이며 무노출 보증이 아니다.

- 소스 기준: `b3b76868eb9348c9a74228591a8521acf417eaaa`와 점검 당시 미커밋 변경.

## 확인된 항목

### P1 — 이미 공개된 모델 저장소의 커밋 이메일

모델 저장소의 두 커밋 모두 작성자와 커미터에 같은 개인 Gmail 주소
`<mailbox>@gmail.com`이 기록되어 있다. 소스 저장소의 109개 커밋에서도 같은 주소를
확인했다. 작성자 표시 이름은 공개 저장소 계정명과 일치한다.

- 공개 커밋: `a3715fd89356cb31b656660354eb563174d64f3e`,
  `e6827c5cbe7c781bf1e6bcb531a0cb1877131ca1`.
- 공개 모델 저장소는 이 점검 시 이미 공개되어 있었고, 소스 저장소는 비공개다.
- 공개 GitHub 프로필의 이메일 필드는 비어 있지만 커밋 기록에서는 주소를 얻을 수 있다.
- 모델 저장소 생성 과정에서 기본 Git 작성자 정보가 들어갔다. 의도한 공개 연락처인지
  확인하기 전까지는 개인정보 정리 대상으로 취급하는 것이 적절하다.

권고: 향후 커밋은 GitHub noreply 주소를 사용한다. 설정 변경만으로 기존 커밋의 주소는
사라지지 않는다. 기존 공개 모델 이력과 향후 공개할 소스 이력은 별도로 정리해야 한다.
이력 변경은 커밋 ID·태그·기존 복제본에 영향을 주며, 이미 복제된 정보의 회수를
보장하지 않는다. 이번 점검에서는 이력이나 원격 저장소를 변경하지 않았다.

배포 소스 ZIP에도 들어 있다. 또한 개발·측정 환경의 로컬 드라이브 절대 경로 17곳이
아래 세 문서와 소스 ZIP에 남아 있다. 이는 개인 이름의 직접 증거보다는 환경 정보 노출이다.

### P2 — 배포 앱의 Python 캐시에 사용자 홈 경로 잔존

다음 ZIP 구성원의 바이트 문자열에 현재 개발자의 사용자 홈 절대 경로가 들어 있다.

`ScreenTo3D-1.0.0/packages/packaging/licenses/__pycache__/__init__.cpython-313.pyc`

배포 앱 ZIP과 최근 로컬 앱 후보 ZIP에서 동일한 파일을 확인했다.
원래 라이브러리는 타사 패키지지만, 이 경로는 공급업체의 빌드 계정 경로와 달리
현재 개발자의 사용자 홈과 일치한다. 현재 프로젝트 루트 전체와는 일치하지 않는다.
캐시 파일 SHA-256은
`123e768453297c7735f6d90744bbf4f26dee6b9c7e9bb1b3670edd6ce16e5a3c`다.

권고: 패키징 시 불필요한 `__pycache__`를 제외하거나 가상 경로로 재컴파일한다.
그 뒤 새 ZIP의 경로 검색과 앱 실행 검증을 수행한다. 이번에는 ZIP을 수정하지 않았다.

## 정리 대상에서 제외한 항목과 음성 결과

- 인식하는 API 키·GitHub/공급자 토큰·개인키·JWT·긴 문자열 자격증명 패턴은
  검사한 텍스트 범위에서 발견되지 않았다. 일반 이메일 노출과 비밀키 유출은 구분했다.
- 라이선스에 명시된 upstream 연락처는 정상 저작권 정보로 분류했다.
- Qt 리소스의 `@2x.png` 이름은 이메일 오탐이다.
- `0.1.0.1` 등의 버전 번호는 사설 IP 오탐이며 `DESKTOP-README.txt`는 PC 이름이 아니다.
  GPU UUID 테스트 값도 정해진 fixture로 확인했다.
- Qt DLL 등에서 공급업체 빌드 계정 경로가 검출됐다. 사용자 경로 캐시와 구분했고,
  서명·무결성에 영향을 줄 수 있는 타사 바이너리 변경은 권하지 않는다.
- 이미지 9개에서 EXIF 정보나 눈에 띄는 개인 파일 경로·연락처·개인 창 제목은
  확인되지 않았다. 파일 변환 UI의 예제 파일명과 Spring 공개 영상 표시를 확인했다.
- 공개 Base·VDA ZIP에는 선택한 개인정보 패턴 후보가 없었다. 모델 가중치의
  의미적 정보나 모든 바이너리 문자열을 검사했다는 뜻은 아니다.

## 근거와 한계

로컬 근거는 Git에서 제외된 `out/privacy-audit-20261112/`에 있다.
`inventory.json`, `candidates.json`, `validated-patterns.json`, `release-supplement.json`,
`release-triage.json`, `public-profile-check.json`, `animation-inspection.json`을 사용했다.
후보 값은 마스킹하거나 실행별 HMAC 지문으로 기록했으며 민감한 원문은 보존하지 않았다.

선택한 Git blob과 ZIP 구성원에는 크기 때문에 건너뛴 항목이 없다. 다만 바이너리 검사는
사용자 경로·기기 식별자 중심이고, 큰 ONNX/DLL은 제한된 ASCII 패턴을 스트리밍 검색했다.
전용 비밀 탐지 엔진·일반 고엔트로피 탐지·바이너리 역분석·전면 OCR은 수행하지 않았다.
개인의 실명·주소·자유 서술 정보는 패턴만으로 완전히 판별할 수 없다.

도달 불가능한 Git 객체, 다른 복제본·포크·GitHub 캐시, 과거 폐기 배포본,
전체 타사 런타임 팩, 로컬 ignored 로그·사용자 설정 전체는 범위에 포함하지 않았다.
현재 로그·캡처의 런타임 개인정보 처리 검토도 별도다.

이번 작업은 점검과 보고서 작성만 수행했다. 제품 코드·기존 문서·배포 ZIP·Git 이력·
공개 범위를 수정하지 않았고 커밋·push도 수행하지 않았다.
