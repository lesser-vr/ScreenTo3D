# 큰 시차의 부드러운 압축 — 2026-11-06

## 범위와 판단

사용자가 선택한 [추가 검토 1번](../references/2026-11-06-owl3d-iw3-quality-followup.md)의
독립 CUDA 구현이다. Owl3D 코드·상수·모델을 복사하지 않았다. 현 깊이 모델,
시간 이력과 고정 수렴점을 유지하고 투영 직전 시차만 변경한다. 새 가중치나
의존성을 설치하지 않는다. 준비된 로컬 Small/Base 라이브 기본은 `budget`이며
기존 `window`는 진단 비교용으로 유지한다. 실제 Owl3D 편안함은 미확인이다.

## 비교 계약과 곡선

같은 RGB·정규화/모션 보정 완료 깊이·강도·수렴점에서 기존 선형 시차와 비교한다.
전체 RGB 동일성은 의도한 변경의 기준이 아니다. 다음 조건을 검사한다.

- 작은 시차는 비트 단위로 보존, 큰 시차는 크기만 감소.
- 좌우 방향과 깊이 순서 보존. 화면면에서 양안 RGB가 원본과 동일.
- 정상 범위와 압축 구간 사이 기울기가 연속. 강도가 커지면 시차도 계속 증가.
- 고정 설정의 동일 좌표에서 시간별 시차 변화량을 증폭하지 않음.
- 가장자리 가림은 보정 후 실제 시차로 계산. Host/native/VFG 원본 출력 일치.
- 꺼진 경로는 이전 고정 `live-depth-window` DLL과 정확히 동일.

`d=(depth-convergence)*scale`는 양안 전체 시차다. 양수는 화면 앞으로 나온
전경, 음수는 화면 뒤 배경이며 기준 `W`는 SBS 전체 폭이 아닌 한쪽 눈의 폭이다.

| 방향 | 그대로 유지하는 크기 k | 점근 상한 L | 1920px에서 k / L |
|---|---:|---:|---:|
| 전경 | 0.25% W | 0.60% W | 4.80 / 11.52px |
| 배경 | 0.35% W | 0.80% W | 6.72 / 15.36px |

`abs(d)<=k`는 원래 값을 반환한다. 나머지는 부호를 유지하며
`k+(L-k)*(abs(d)-k)/(L-k+abs(d)-k)`로 변환한다. 기울기는 경계에서 1,
압축 구간에서 0보다 크고 1 이하이다. 급격히 잘라낸 평면이나 깊이 역전을
만들지 않는다. 화면 통계로 상한/수렴점을 움직이지 않아 이 보정에 의한
통계 기반 펌핑이나 새 프레임 이력이 없다. 상한은 초기 렌더링 설계값이며
시청 거리·눈 간격·표시 크기를 반영한 생리학적 안전 보증이 아니다.

강도 기본값 0.5와 무제한 출력 기본값은 그대로다. 압축 구간에서는 강도를
높여도 기존 선형 방식보다 증가폭이 작다. 추가 사용자 옵션은 없다.
파일/reference, RowFlow, VDA/oVDA는 이 보정을 사용하지 않는다.

## 공개 영상, 같은 깊이의 전후 비교

FloorballGame / OfficeWalk / ParkingGarage 각 90 연속 프레임, Base/Small 각
270프레임, 1920×1080, source clock 60Hz, 강도 0.5. 실제 모델 추론, 범위
안정화와 GPU 모션 이력을 거친 하나의 깊이를 각 시차 계산에 공유했다.
프레임 0/45 및 검출 컷에서 이력을 초기화한다. 입력 출처/허가는 결과 JSON의
`attribution`에 보존했다. 개인 화면은 저장하지 않았다.

수치는 프레임별 절대 양안 시차 통계의 평균이며 단위는 픽셀이다.

| 모델 / 영상 | 전체 P50 전→후 | 전체 P95 전→후 | 전체 최대 전→후 | 중앙 1/3 P95 전→후 |
|---|---:|---:|---:|---:|
| Base / Floorball | 8.221→7.391 | 12.706→9.514 | 13.728→9.684 | 7.903→7.745 |
| Base / Office | 4.844→4.834 | 11.238→9.205 | 13.728→9.680 | 5.891→5.889 |
| Base / Parking | 7.498→7.001 | 12.348→9.668 | 13.728→9.684 | 8.670→8.280 |
| Small / Floorball | 5.680→5.626 | 8.785→7.555 | 9.504→7.661 | 5.421→5.421 |
| Small / Office | 3.480→3.480 | 7.940→7.389 | 9.495→7.649 | 3.856→3.856 |
| Small / Parking | 5.051→5.046 | 8.591→7.632 | 9.504→7.661 | 5.505→5.505 |

전체 P95 감소는 Base 18.1–25.1%, Small 6.9–14.0%이다. 중앙 영역의 P50은
모든 프레임 쌍에서 동일하다. 중앙 P95 감소는 Base 0.04–4.50%, Small 0%다.
이는 중앙 피사체 인식이나 주관적 입체감 보존 시험이 아닌 공간 영역 통계다.

컷/강제 초기화를 제외한 동일 픽셀의 프레임 간 시차 차이는 모든 검사 지점에서
증가하지 않았다(부동소수점 허용 0.00005px). 평균 시간 차이 P95는 Base
0.1104→0.0900 / 0.5382→0.4617 / 0.0328→0.0298px, Small
0.0719→0.0695 / 0.3952→0.3667 / 0.0369→0.0366px이다.
이 결과를 움직임 정렬 오차나 모델의 일렁임이 같은 비율로 해결됐다는 뜻으로
해석하지 않는다. 원래 깊이 오차·가림 합성의 오류는 남는다.

## GPU 정확성·비용

독립 float64 수식과 실제 GPU shift를 0.00004px 오차 내 비교했다. 16×16,
64×32, 1920×1080, 3440×1440, 1080×1920, 3840×2160, 4096×2160 각각
강도 0.25/0.5/2로 21조건을 검사했다. 단조 깊이 순서, 선형 코어 exact,
부호, 상한, 비활성화 이전 DLL exact, 실제 가림 폭, native RGBA exact를 통과했다.
추가 세 평면의 실제 RGB 중심으로 좌우 방향을 검사했고 화면면 RGB는 exact다.
GPU 시간 변화 검사와 잘못된 활성화 값/빈 핸들 거부도 통과했다.

동일 합성 깊이와 공개 RGB, 네이티브 투영·게시의 on/off 교차 반복, 조건별
10회 워밍업 후 50회 측정이다. 명시적 readback은 측정 구간 밖이다.

| 한쪽 눈 크기 | 기존 중앙값→보정 중앙값 | 기존 P95→보정 P95 |
|---|---:|---:|
| 1920×1080 | 0.4412→0.4343ms | 0.7166→0.7401ms |
| 3840×2160 | 1.8321→1.8349ms | 2.5368→2.3373ms |

증가 비용이 작게 관측되지만 잡음이 있으며 속도 향상을 주장하지 않는다.
WGC·추론·VFG·Qt·물리 출력은 제외되어 전체 FPS나 장시간 성능을 입증하지 않는다.
정상 경로에 새 GPU 할당·CPU readback·동기화는 없다.

6조건 exact와 실제 VFG 1080p/4K 생성까지 통과했다. 생성 영상의 보호 검은
열은 Base [8,8]/[17,17], Small [7,7]/[15,15], 최대 RGB 모두 0이었다.
이는 생성 영상 전체의 양안 화질 평가가 아니다. CPU 회귀 243개 및 VFG 계약
12개도 통과했다. RowFlow는 공유 RGB/깊이 연결부 exact만 검사했으며 학습형
합성과 사용자 시각 비교는 재개하지 않았다.

새 공유 구조에서 Small 전처리 27조건과 host/GPU/native 출력 72조건,
기존 window 합성 회귀 105조건, 모션 이력 합성 회귀도 통과했다. 결과는
`small-parity/report.json`, `window-regression.json`, `motion-regression.json`,
`rowflow-layout.json`, `cpu.json`에 있다.

실제 Base A 및 Small VFG GUI에서 공개 영상 소스 선택, 시작 버튼,
강도 0.5 초기값/재설정, `stereo_quality=budget`, 출력 캡처 정책과 프로세스 간
재캡처 거부, 연결된 두 화면 이동, F11 전체 화면, 숨김/복원, 중지/재시작/닫기를
확인했다. 두 경로 모두 종료 후 `live_pools=0`, `live_nodes=0`, `has_frame=false`다.
`base-gui/smoke.json`, `small-vfg-gui/smoke.json` 및 각 session JSON이 근거다.
이 검사는 실제 Qt/네이티브 실행 확인이며 물리 Owl3D 입체 시청 평가가 아니다.
변경 Python 범위의 Ruff E9/F와 diff 공백 검사도 통과했다.

## 미확인 사항

물리 Owl3D에서의 눈 편안함·입체감, 실게임과 장시간 시청은 별도 확인 대상이다.
빠른 움직임의 얇은 윤곽·드러난 배경·VFG 합성 품질은 이 압축이 직접 해결하지
않는다. 화면 크기/거리나 표시 방식이 바뀌면 같은 폭 비율도 체감이 달라진다.
이전 앱 프로세스는 다시 실행해야 새 로컬 모듈을 읽는다. 기존 비교 실행기의
사용 방법은 동일하며 portable 배포본에는 자동 반영되지 않는다.
