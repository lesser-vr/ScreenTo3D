# Base·VDA 공개 배포 저장소 분리 검토

검토일: 2026-11-12. 조사와 로컬 ZIP·코드 확인만 수행했다. 저장소 생성·공개,
업로드, 앱 동봉 정책 변경, commit/push는 수행하지 않았다. 소스 저장소도 추후
공개한다는 사용자의 방향을 반영한 제안이며 현재 제품 정책을 대체하지 않는다.

## 권고

**소스·앱은 `lesser-vr/ScreenTo3D`, 자체 변환한 모델 팩은 별도 공개 저장소
`lesser-vr/ScreenTo3D-Models`의 Releases에서 배포**하는 구성을 권장한다.
저장소 이름은 제안이며 생성 여부·이름 사용 가능 여부는 확인하지 않았다.

소스도 공개하면 두 저장소 모두 익명 다운로드가 가능하므로, 분리의 이점은 인증이
아니라 앱/모델의 독립적인 버전 관리와 배포 수명이다. 앱의 문서·UI 수정 때마다
같은 모델 수백 MB를 다시 올리지 않아도 되고, 오래된 앱이 참조하는 모델 주소를
보존하기 쉽다. Git 이력에는 README, 모델 설명, 출처·변환 정보, 라이선스,
릴리즈 메타데이터만 두고 큰 ZIP은 Release 첨부 파일로 둔다.

통합 저장소도 기술적으로 가능하며 초기 관리 대상은 하나 적다. 다만 현재의 모델
용량과 고정 해시 기반 설치 구조에서는 별도 저장소의 작은 운영 부담보다 버전
독립성의 이점이 크다고 판단한다. 분리 자체가 전송 속도를 높이지는 않는다.

## 공개 범위와 용량

| 구분 | 현재 팩 | 정확한 바이트 | 공개 내용 |
| --- | --- | ---: | --- |
| DA2 Base | `da2-base-onnx-v1.zip` | 392,348,171 | 518x896/924 혼합 FP16 ONNX 2개, 검증 샘플, NOTICE |
| VDA Small | `vda-small-onnx-v3.zip` | 363,291,834 | 두 비율의 warmup/cached ONNX 4개, 검증 샘플, Apache LICENSE·NOTICE |

실제 팩의 ZIP 항목을 확인했다. 사전 생성 TensorRT 엔진, NVIDIA 런타임,
원본 영상은 들어 있지 않다. 모델 ZIP 외에 출처·라이선스·해시를 설명하는 작은
문서는 함께 공개한다. TensorRT·CUDA·FFmpeg·VFG는 앞서 구성한 공식 원본
다운로드 경로를 계속 사용하고 이 저장소에는 재업로드하지 않는 안이다.

현재 앱 ZIP은 822,256,200바이트다. 그 안의 모델 ZIP 항목이 차지하는 압축
크기는 각각 362,854,519 / 276,628,304바이트다. 이 두 항목을 제외하면
**182,773,377바이트, 약 183MB**로 추산된다. ZIP 디렉터리 오버헤드와 향후
메타데이터 변경 전의 계산이며 실제 분리 빌드를 생성·측정한 값은 아니다.
현재 모델 팩 자체는 ZIP_STORED로 만들어져 있으므로 공개 시 다운로드량은
Base 약 392MB, VDA 약 363MB다. 압축 방식을 바꾸면 팩 버전·크기·해시도
바뀌므로 이번 배포 구조 제안과 별도 변경으로 취급한다.

## 모델별 라이선스

**Base:** 공식 모델 카드는 CC BY-NC 4.0이다. 해당 라이선스는 비상업적 목적의
공유와 변경본 공유, 필요한 기술적 형식 변환을 허용한다. ONNX/FP16 변환이나
별도 공개 저장소 사용으로 비상업 조건이 없어지지 않는다. 저작자·원본 URL,
라이선스·면책 관련 고지, 변경 사실을 보존해야 한다. 무료 다운로드라는 사실만으로
배포·이용의 목적이 비상업적이라고 자동 확정되지는 않는다. 유료 앱 또는 상업적
운영에 Base를 제공할 경우 별도 권한 확보 여부를 확인해야 한다.
[공식 Base 모델 카드](https://huggingface.co/depth-anything/Depth-Anything-V2-Base),
[CC BY-NC 4.0 본문](https://creativecommons.org/licenses/by-nc/4.0/legalcode.en).

**VDA Small:** 공식 모델 카드가 Apache 2.0을 명시한다. 라이선스 사본, 적용되는
저작권·NOTICE 고지, 변경 표시를 보존하는 조건으로 재배포할 수 있으며 상업적
이용도 허용되는 라이선스다. 다른 VDA 변형까지 같은 조건이라고 일반화하지 않는다.
[공식 VDA Small 모델 카드](https://huggingface.co/depth-anything/Video-Depth-Anything-Small),
[Apache 2.0 본문](https://www.apache.org/licenses/LICENSE-2.0).

두 팩을 저장소 전체의 단일 MIT/Apache 라이선스로 표기하면 안 된다. 모델별로
라이선스를 구분하고 ScreenTo3D가 변환한 비공식 배포임을 명시한다. 현재 Base
NOTICE에는 원본·라이선스 링크와 혼합 FP16 변경 설명이 있고 VDA에는 Apache
본문과 변경 설명이 있다. 공개 배포 시에는 다음 정보를 보강하는 안을 권장한다.

- 모델 카드와 출처 manifest: 원본 source/weights revision·SHA-256, 변환 도구
  revision, 그래프별 SHA-256, 정밀도·고정 입력 형태, 검증 계약·지원 범위.
- 모델별 라이선스 본문과 저작자·면책·변경 고지. CC는 본문 또는 라이선스 URL을
  허용하므로 현재 Base에 본문 파일이 없다는 사실만으로 위반이라고 단정하지 않는다.
- 모델 카드의 검증 GPU와 이용 가능한 GPU를 구분. ONNX 배포와 사용자 GPU의
  엔진 생성은 모든 NVIDIA GPU에서의 실제 검증을 의미하지 않는다.

원본 revision은 기존 로컬 기록에서 확인할 수 있다:
`docs/evidence/da2-base.md`, `docs/evidence/vda.md`. 검토 시 팩에는 완전한
기계 판독 출처 manifest가 없었다. 외부 동반 문서 보강만 하면 기존 ZIP 해시는
유지할 수 있다. ZIP 내부를 보강한다면 새 팩 버전과 해시로 배포해야 한다.

소스 저장소를 공개하는 것과 오픈소스 이용 허락은 별개다. 현재 루트에 프로젝트
전체 LICENSE/COPYING 파일은 확인되지 않았으므로 앱 코드의 라이선스는 공개
준비 때 별도로 정하고, 모델별 라이선스와 구분해 표시할 필요가 있다.

## 버전과 다운로드 신뢰 경로

초기에는 두 팩을 묶는 고정 모델 릴리즈 태그(예: `packs-2026.11.1`)를 사용하면
현재의 단일 `model-origin.txt` 디렉터리 구조를 재사용할 수 있다. 다음 URL은
생성하지 않은 제안 주소다.

```text
https://github.com/lesser-vr/ScreenTo3D-Models/releases/download/packs-2026.11.1/
  da2-base-onnx-v1.zip
  vda-small-onnx-v3.zip
```

앱은 버전이 고정된 주소와 자체 보유 size/SHA-256을 신뢰한다. `latest`나 서버의
가변 manifest만으로 새 모델을 자동 신뢰하지 않는다. 공개 `SHA256SUMS`와
manifest는 배포 점검·사용자 확인용이며 앱의 내장 pin을 대체하지 않는다.
기존 태그·파일은 덮어쓰지 않고, 변경 시 새 버전·태그로 게시한다. 원격 장애에도
검증된 로컬 캐시 또는 사용자 지정 파일을 사용할 수 있게 한다.

장기적으로 모델별 독립 태그가 필요하면 key별 URL 카탈로그를 도입할 수 있다.
현재 코드는 한 origin에 파일명을 붙이므로 모델별 태그를 그대로 연결할 수 없다.
이는 초기 분리의 필수 조건은 아니다. 공개 팩 게시 권한은 유지보수자에게만 주고,
소스 저장소 CI가 외부 저장소에 자동 게시한다면 해당 저장소 쓰기 권한을 가진
배포용 자격 증명을 CI에만 둔다. 사용자 앱에는 토큰을 넣지 않는다. 초기에는
수동 게시도 가능하다.

GitHub는 공개 Release asset의 무인증 접근을 지원하고, 총 Release 크기·대역폭
사용량 한도는 없다고 명시한다. 파일별 2GiB 미만, Release당 최대 1000개 제한에
두 팩 모두 여유 있게 들어간다. 이를 속도·가용성 보장으로 해석하지 않는다.
REST 메타데이터 호출은 익명 IP당 시간당 60회 한도가 따로 있으므로 정상 설치는
고정 직접 URL을 사용한다.
[공개 asset 접근](https://docs.github.com/en/rest/releases/assets#get-a-release-asset),
[Release 한도](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases#storage-and-bandwidth-quotas),
[REST 한도](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api).

## 앱·빌드 변경과 UX

현재 `source_for()`는 앱 내부 팩 → 인접 로컬 팩 → 설정된 HTTPS origin 순으로
찾는다. 원격 파일에도 전체 SHA-256, 크기 검사, 캐시·이어받기·취소·재시도를
이미 적용한다. `--model-origin`도 있다. 그러나 빌더가
`bundle_model_packs()`를 항상 호출하므로 **origin 설정만으로 앱이 작아지지는
않는다**. 외부 다운로드용 빌드에서 Base·VDA 동봉을 생략하고 패키징 메타데이터와
별도 optional-models ZIP 자동 생성을 함께 조정해야 한다.

권장 사용자 흐름은 기존 설치 창을 유지하는 것이다. Small은 앱에 포함한다.
Base/VDA를 선택하고 작업을 시작하면 필요한 다운로드 크기, 모델 이용 조건,
다운로드 후 GPU 최적화 단계를 표시한다. Base에는 비상업 조건을 명시한다.
사용자가 설치를 시작하면 다운로드 → 검증 → 엔진 최적화 → 요청 작업으로
이어지며, 취소·실패 시 작업을 자동 실행하지 않는다. 로그인·브라우저 이동·
수동 파일 준비가 정상 경로에 들어갈 필요는 없다. 네트워크 실패 시 기존 재시도와
파일에서 설치를 제공한다. 파일 변환 기본 모델이 Base이므로 첫 파일 변환에서는
약 392MB의 모델 다운로드와 공통 런타임 준비가 발생한다는 점도 표시한다.

시행 시 필요한 확인은 새 빌드의 동봉 제외·실제 크기, 팩별 익명 직접 다운로드,
중단·이어받기·변조 거부, 캐시 재사용, 새 GPU 엔진 생성, live/file 설치 재개다.
이번에는 공개 저장소가 없으므로 해당 주소의 다운로드나 분리 빌드는 실행하지
않았다. 현재 구현·기존 팩과 공식 정책을 근거로 실행 가능한 배포안을 검토했다.
