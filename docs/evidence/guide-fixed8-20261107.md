# 반경 8 깊이 경계 보정 최적화

RTX 5090의 준비된 로컬 앱에서 DA2 Small과 Base의 반경 8 계산을 고정 크기 CUDA 커널로 바꿨다. 출력 픽셀마다 17개 이웃의 합을 구하는 가로·세로 패스를 GPU에서 병렬 실행한다. 기존 반경 4에서 검증한 두 성분 FP32 누적을 재사용하고 평균을 구할 때 FP64로 결합한다. 가이드 반경, 원본 해상도, 경계 반사 규칙, 시간 안정화 설정은 기존판과 같다. 비교 기준은 직전 배포 경로인 `guide-common`의 반경 8 rolling 합산이다.

## 같은 입력에서의 결과

`v1/check_da2_radius8.py`가 모델별로 한 번 계산한 깊이를 이전·새 렌더러에 공급했다. 같은 RGB, 타임스탬프와 강도 0.5, 독립적인 깊이 이력, 실제 네이티브 텍스처 출력을 사용했다. 5개 공개 영상(4K Jockey/Beauty, 1080p FloorballGame/OfficeWalk/ParkingGarage)과 513×289 얇은 선·균일 배경 합성 영상 각각에서 두 모델로 36프레임씩 처리했다. 매 18번째 프레임에서 이력을 초기화했다.

- 432프레임 쌍에서 최종 좌우 영상의 RGBA 바이트가 모두 일치했다. 진단 깊이의 최대 절대 차이는 2.38e-7, 프레임별 평균 절대 차이의 최댓값은 1.97e-13 이하였다. 수치 결과는 해당 입력에 대한 비교다.
- GPU 시간은 반경 8의 네 패스에 놓인 CUDA 이벤트 5–6으로 측정했다. 첫 6프레임을 제외한 30쌍의 실행 순서를 번갈아 측정한 4K Jockey 중앙값은 Base 2.84→0.57ms, Small 3.50→0.57ms였다. 4K Beauty는 Base 2.84→0.58ms, Small 2.70→0.58ms였다. 1080p 세 영상에서는 두 모델 모두 약 0.34–0.35→0.14–0.15ms였다.

프레임별 값은 준비된 체크아웃의 `out/guide-fixed8/quality/`에 있다. 별도 4K Base 단계 측정은 `out/guide-fixed8/guide-timing.json`에 있다.

## 네이티브 SBS 재생

RTX 5090에서 mpv로 재생한 4K 120 FPS Jockey 창을 캡처해 7680×2160 SBS로 출력했다. 출력 제한은 60 FPS, 입체감은 0.5, VFG는 꺼짐이었다. 각 조건에서 10초씩 세 구간을 측정했다.

| 모델 | 출력 FPS (이전 → 적용) | GPU 전체 평균 점유율 | GPU 전체 평균 전력 |
| --- | ---: | ---: | ---: |
| DA2 Small | 60.00 → 60.00 | 52.60% → 38.13% | 236.38 → 212.37 W |
| DA2 Base | 59.50 → 59.90 | 71.01% → 56.00% | 331.45 → 308.71 W |

점유율과 전력에는 플레이어와 바탕 화면이 포함된다. 각 실행 전 바탕 화면의 GPU 점유율도 3.52–9.28%로 차이가 있었다. 측정 원본은 `out/public-hfr/radius8*.json`에 있다.

VFG 설정 전환을 포함한 5회 세션에서 모두 프레임이 제출됐고 종료 후 추적 자원이 0으로 돌아왔다(`out/guide-fixed8/runtime/result.json`). 새 DLL에서 RowFlow 브리지로 복사한 RGB와 보정 깊이도 193×73 입력에서 원본 버퍼와 일치했다.
