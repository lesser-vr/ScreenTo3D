# 입체감 0.5 기준의 추가 일렁임 개선 검토

2026-11-06. 사용자는 이전 개선 후에도 일렁임을 보고했고, 이번 검토 중
**입체감 0.5에서 Owl3D Live 3D와 비슷한 느낌**이라고 설명했다. 이를 다음
비교의 기준으로 삼는다. 모든 장면의 화질·편안함을 승인했다는 뜻으로 확대하지
않는다. 이번 작업은 원인 분리와 오프라인 후보 평가이며 앱 기본값은 변경하지 않았다.

## 판단

다음 우선순위는 **가림 경계의 연속적인 합성**이다. 기존 서브픽셀 보정으로
줄어든 것은 같은 표면 안의 정수 위치 오차다. 앞/뒤 물체 사이의 윤곽에서는
여전히 하나의 픽셀 소유자를 선택하며, 원래 구멍 메우기를 그대로 쓴다.
깊이를 더 강하게 평균내는 것만으로는 이 출력 단계의 불연속이 사라지지 않는다.

그 다음은 **신뢰할 수 있는 물체 대응을 이용한 깊이 범위/이력 안정화**다.
단순한 CPU optical flow 후보는 측정 비용에 비해 이득이 작았고, 경계에는
효과가 없었다. 자동 수렴점과 입체감 자동 증폭을 먼저 적용할 근거는 없다.

## 이번에 확인한 것

### 1. 강도 0.5에서도 가림 경계는 한 픽셀씩 변한다

실제 현재 GPU DLL에 빨간 전경과 파란 배경을 입력했다. 전경의 연속적인
투영 이동이 정수 위치를 지나는 0.1 px 구간을 21단계로 나눠 비교했다.

| 강도 | 전경 이동 범위 | 관측한 왼쪽 경계 | reference/subpixel |
|---|---|---|---|
| 1.0 | 9.95–10.05 px | 709→710, 1 px 전환 | 전체 출력 동일 |
| 0.5 | 4.95–5.05 px | 704→705, 1 px 전환 | 전체 출력 동일 |

이것은 실제 사용 장면의 원인을 확정하는 테스트가 아니라, 출력기에 남은
불연속을 분리한 재현이다. 이동 범위가 의도적으로 픽셀 경계를 지나도록
구성됐다. 강도를 낮추면 깊이 오차에 따른 시차 진폭은 줄지만, 픽셀 경계를
지나는 순간의 hard coverage 전환 자체가 제거되지는 않는다.

코드 근거: `projection.cu::splat`의 floor/ceil + atomicMax 소유자 선택,
`live_depth.cu::reconstruct_subpixel`의 기존 소유자 유지와 깊이 차이 0.01
이웃 거부, `resolve`/병렬 대응 코드의 기존 빈 영역 처리.

### 2. 움직이는 영역은 깊이 시간 보정을 상당 부분 건너뛴다

현재 Base FP16과 실제 CUDA 후처리를 사용했다. 1080p 공개 RGB, 세 클립 각
3초 중 60 Hz의 매 두 번째 프레임을 처리해 각 90회 새로 추론했다. 시작과
중간 강제 컷에서 초기화했다. 컷을 제외한 프레임의 전체 픽셀 평균:

| 영상 | RGB 변화로 이력 거부 | EMA 적용 가능 |
|---|---:|---:|
| FloorballGame | 32.6% | 67.4% |
| OfficeWalk | 69.3% | 30.5% |
| ParkingGarage | 13.4% | 86.5% |

색 변화 0.04를 넘는 픽셀 주변 7x7을 거부하며, 깊이 차이 0.08도 검사한다.
GPU에서 읽은 normalized/smooth 깊이와 동일 계산을 비교해 최대 차이가
2e-6 미만인지 검증했다. 이 거부는 잔상을 막는 장치다. 단순히 없애거나
임계값을 크게 하면 다른 물체의 이전 깊이가 섞일 수 있다. EMA 계수만
낮추어도 거부된 영역에는 평균이 적용되지 않는다.

### 3. 기존 한 프레임 모션 정렬 후보는 경계 해결책이 아니다

현재 CUDA 후처리 결과를 480x270 격자로 줄인 뒤 기존 `align_history`를
적용했다. FAST 양방향 DIS, 광도/전후방 일치/깊이/경계 검사를 사용하며,
이전 **필터 전** 깊이 한 장만 참조한다. 이전 필터 결과를 재귀적으로 넣거나
현재 추론을 생략하지 않았다. 거부된 픽셀과 컷은 현재 깊이 그대로인지 검사했다.

평가는 별도 MEDIUM DIS로 정렬한 광도 일치 영역에서 수행했다. 필터와 평가의
flow preset은 다르지만 모두 DIS이므로 독립적인 깊이 정답을 대신하지 않는다.
아래 시차 단위는 1920 px/강도 1.0으로 환산한 깊이 차이다. 강도 0.5에서는
이 연속 시차 지표가 수학적으로 절반이며, 실제 출력 윤곽 오차가 절반이라는 뜻은 아니다.

| 영상 | 전체 시차 오차: 현재→후보 | 변화 | 경계 오차: 현재→후보 |
|---|---:|---:|---:|
| FloorballGame | 0.11070→0.10449 px | -5.6% | 0.57899→0.57916 px |
| OfficeWalk | 0.44547→0.42758 px | -4.0% | 0.80114→0.80167 px |
| ParkingGarage | 0.05783→0.05475 px | -5.3% | 0.16523→0.16531 px |

경계의 현재 후보 깊이 변화는 정확히 0이었다. 후보가 그 영역을 의도적으로
거부하기 때문이다. 경계 시계열 오차의 아주 작은 증가는 이전 프레임의
비경계 위치가 정렬 시 참조될 수 있어서 생긴다. 전체 평균의 소폭 개선을
윤곽 일렁임 해결로 해석하면 안 된다.

CPU 한 스레드에서 flow 2회+검사+혼합에 평균 7.00–7.29 ms가 추가됐다.
전처리·모델·전체 해상도 복원·SBS·표시를 제외한 비용이다. 이전 Distill
518x518 실험의 26 ms와 모델/격자/삽입 위치가 달라 직접 속도 향상 비교는
할 수 없다. 이 CPU 후보는 기본 경로에 적용하지 않는다.

### 4. 깊이 범위 갱신도 화면 전체 시차에 영향을 준다

같은 현재 raw depth를 사용하면서 GPU의 현재 2/98 백분위 EMA 범위를 적용한
경우와 바로 전 프레임의 범위를 고정한 경우를 비교했다. 차이는 범위 갱신에
의한 영향만 분리하며, 어느 쪽이 정확한지를 뜻하지 않는다.

강도 1.0/1920 px 기준 전체 평균 영향은 FloorballGame 0.067, OfficeWalk
0.184, ParkingGarage 0.028 px였다. 프레임별 P95의 평균은 각각 0.159,
0.400, 0.068 px였다. 강도 0.5의 연속 시차 영향은 절반이다. 범위를 무조건
고정하거나 느리게만 바꾸면 상대 깊이 모델의 실제 scale/shift 변화에 뒤처질
수 있으므로, 대응 물체의 안정성과 장면 내용 변화를 함께 구별해야 한다.

## 권장 개선 순서와 확인 기준

1. **윤곽 커버리지와 가림 합성 개선.** 기존 단일 정수 소유자 이후의 색 보정만
   하지 말고, 전경이 픽셀을 차지하는 연속적인 면적과 드러난 배경을 합성한다.
   얇은 물체, 전경 뒤로 보이는 배경, 글자/철망, 반복 좌우 이동에서 경계 이동의
   연속성과 전경/배경 색 번짐을 함께 비교한다. 위 두 강도의 경계 재현을
   독립 기준으로 유지하고, 근거리 물체가 흐릿해지면 개선으로 인정하지 않는다.
2. **깊이 범위와 이력의 시간 안정화.** 화면상의 같은 좌표가 아니라 신뢰할 수
   있는 물체 대응을 사용한다. 안정된 영역의 raw depth scale/shift를 추정하고,
   내용 변화로 인한 범위 이동을 구별하는 후보를 비교한다. 프레임 수에 고정된
   EMA 대신 실제 시간 간격에 따른 완화도 함께 평가한다. 컷/새로 드러난 영역은
   현재 깊이를 유지하며, 느린 반응·깊이 고착·추적 오류를 따로 측정한다.
3. **GPU 모션 보정의 선택적 적용.** 신선한 DA2 추론을 유지한 채 낮은 격자의
   대응 정보만 활용하고, 신뢰도에 따라 이력 비중을 연속적으로 바꾸는 후보다.
   CPU 후보의 작은 전체 개선만으로 통합하지 않는다. 기존 NVOF 자원 경계를
   재사용할 수 있으나 비용/품질은 다시 검증해야 한다. 과거 recurrent oVDA
   추론을 절반 생략한 실험과 다른 비교 계약이다.
4. **화면 가장자리 돌출 제한과 장면별 시차 예산.** 특히 전경이 화면 밖으로
   잘리는 경우를 대상으로 평가한다. 내용 기반 수렴점보다 먼저 전체 시차
   상한과 시간 변화율을 검증한다. 기본 비교 강도는 사용자 선택 0.5이며,
   중앙 입체감을 과하게 압축하거나 화면 가장자리 물체를 휘게 하면 제외한다.

과거 Owl3D 셰이더 조사에서 연속 가중 합성과 시차 예산/가장자리 처리는
확인했지만, Live 3D의 motion history/내부 모델 상태는 확인하지 못했다.
위 모션 후보를 Owl3D가 쓰는 방식이라고 주장하지 않는다. 독립 구현 후보이며
상용 셰이더나 모델을 복사하지 않았다.

## 실사용 기록과 미확인

최근 `out/vfg-comparison/20261106-094759-5910-A-baseline/`의 4개 기록은
A/Base, VFG 생성 프레임 0이다. 마지막 세션은 강도 0.5, Full SBS 7680x2088,
무제한 출력이며 오류 보고 없이 자원 정리가 끝났다. 따라서 VFG만을 원인으로
지목할 근거는 없다. 다만 이것이 사용자 신고와 정확히 같은 장면이라는 확인은 없다.

출력률은 구간별로 크게 달라지지만 입력 영상의 변화/정지 여부, 원본 캡처
시간 간격 및 reset 사유가 이 기록에는 없어 성능 결함이라고 단정하지 않는다.
다음 실제 비교에는 픽셀/창 제목 없이 해당 수치와 사용 중인 품질 정책을
함께 기록하면 원인 분리에 도움이 된다. 모션 품질 비교는 0.5, 동일 입력,
동일 크기/속도에서 A 경로를 먼저 보고 VFG는 별도로 비교하는 구성이 적합하다.
