# Packaged Small: 30-minute live runtime test (2026-11-18)

Release: ScreenTo3D 1.0.0, commit `0de8d9dff07ce0a508a3ea5600d170d26467d04a`.
This is a single sustained run of the released portable GUI modules, native
binaries and normal worker path through an external diagnostic harness. It is
not an optimization A/B, quality benchmark or cross-GPU acceptance result.

## Conditions

- RTX 5090, driver 621.24; PG32UCWM input display at 239.991 Hz and Owl3D Shift output at 60 Hz.
- DA2 Small FP16, GPU capture/preprocessing and native output, Half Top-and-Bottom, 60 FPS limit, strength 0.5, VFG OFF.
- Actual input client and output buffer both 3840 x 2160 pixels; fullscreen output on Owl3D Shift.
- Local 4K60 H.264 corpus, 37.5 seconds per cycle: FloorballGame 0–7 s, OfficeWalk 7–17 s, ParkingGarage 17–36 s, retained black-background flower TC 36–37.5 s. Public motion clips are from UVG-VCM (CC BY 4.0). The retained scene excerpt is local test use only and is not redistributed.
- mpv D3D11VA decoding with source-rate timing. An initial preflight using display-resample produced duplicate 240 Hz presentations and was corrected before this run. That preflight is not part of the measured interval.
- Two-minute warmup excluded. Settings and session remained fixed for the full measured interval. Existing Owl3D display-mirror and other applications were preserved, so GPU readings include their load.
- PresentMon 2.6.0 collected frame timings, without input-event tracking, pixels or audio. Exact QPC bounds select the 30-minute interval. Resources were sampled approximately once per second.

The first and last nominal five-minute windows each span eight corpus cycles;
the actual sampled rate spans are 299.03 and 299.85 seconds. No sustained late
throughput decline or material memory growth was observed. Playback retained
one native pool and one native node throughout. Stop plus three automatic
restarts passed: live pools/nodes returned to zero and no owned process remained.
Every one-second observation showed output progress; this is distinct from
subsecond display intervals measured by PresentMon.

The 60 FPS submission goal (98% floor, 58.8 FPS) was **not met**. Runtime stability
passing does not make this a sustained 4K60 performance pass. GPU load cannot be
attributed entirely to ScreenTo3D: a point GPU-engine observation showed worker
CUDA 67% and Owl3D 3D 52%. Different engine percentages overlap and must not be
added or treated as shares of whole-GPU usage.

All observed native output presents used SyncInterval 1 and AllowsTearing 0.
That verifies the OS submission settings, not optical absence of tearing.
Owl3D's input target and final content were not independently verified. Its
59.59 FPS display rate does not establish 59.59 newly generated SBS images per
second. Similarly, occlusion of an intermediate SBS window can lower its OS
display count; that count alone is not proof of pipeline frame loss.

## Separate controls checks and remaining evidence

Outside the 30-minute interval, registered fullscreen hotkey-message dispatch
toggled windowed/fullscreen twice. F11/source-focus acceptance remains **partial**:
the output HWND/PID was valid and usable, but Windows rejected automatic foreground
activation while another application retained focus. The harness did not inject
input into that application. Two earlier harness attempts and the final activation
diagnostics are retained; no product F11 defect or pass is inferred from them.
Physical keyboard/mouse dragging, visual help-popup review and binocular comfort
remain unverified. VFG ON/OFF was not reached in these controls checks; VFG was OFF
throughout the sustained run.

The original settings/model stores and unrelated processes were preserved. All
owned source windows, test GUI/workers and the timed recorder exited. Application
code and released assets were not changed. Local raw evidence is retained under
ignored `out/soak-live-20261118/`: `conditions.json`, `summary.json`, `minutes.csv`,
`presentmon.csv`, `sustained/report.json`, `sustained/samples.jsonl`,
`sustained-resources.jsonl`, `sustained-source.jsonl`, and `controls3/report.json`.
Capture-card gameplay, Base/VDA/VFG sustained playback, other GPUs, physical scanout
and eye comfort require separate evidence.
