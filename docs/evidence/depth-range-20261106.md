# 깊이 범위 시간 안정화 — 2026-11-06

## 적용 범위와 동작

준비된 Windows/RTX 5090 앱의 DA2 Small/Base CUDA 실시간 경로에 기본 적용했다.
네이티브/호스트 출력과 Small/A/B 비교 실행기가 공유하며, 입체감 기본 0.5와
기존 coverage 윤곽 보정을 유지한다. 새 GUI 옵션이나 미래 프레임 대기는 없다.
파일·명시적 reference 경로, RowFlow, VDA/oVDA에는 이 범위 정책을 적용하지 않는다.
코드 진단용 `DEPTHSBS_STEREO_QUALITY=coverage`는 이전 범위 정책을 보존한다.

기존 2/98 백분위 범위 EMA는 픽셀 깊이 EMA와 같은 프레임 가중치를 썼다.
새 정책은 다음 두 단계를 구분한다.

1. 이전 범위를 현재 모델의 깊이 단위로 옮긴다. 32×32 고정 표본에서 이전
   정규화 깊이와 현재 raw depth의 선형 관계를 구한다. 3×3 RGB 변화가 채널별
   4/255 이하이고 이전 깊이가 0.05~0.95인 표본만 쓴다. 두 번의 회귀에서
   최소 96개 표본, 깊이 분산 0.005 이상, 80% 이상 잔존, 잔차 RMS 0.015 이하,
   배율 0.8~1.25·이동 ±0.15 조건을 만족해야 보정한다. 두 번째 회귀는 잔차
   0.025 초과 표본을 제외한다. 실패하면 범위 운반 없이 다음 시간 응답을 쓴다.
2. 범위 자체의 작은 변화는 시간상수 150ms로 완화하고, 상대 변화 3~15%에서
   시간상수를 35ms까지 연속적으로 줄여 큰 변화를 따라간다. 가중치는
   `1-exp(-source_dt/tau)`이며 픽셀 EMA 계수와 독립적이다. 양 끝점은 같은
   가중치를 사용한다. 컷·소스/크기 변경·중복/역행 시각·100ms 초과 간격에는
   현 프레임 범위를 즉시 채택한다. 타임스탬프 없는 진단 호출만 1/60초를 쓴다.

추정은 GPU의 256스레드 단일 블록과 공유 메모리에서 수행한다. 기존 이전 RGB,
깊이 및 두 범위 값만 재사용한다. 추가 프레임 버퍼·CPU 깊이 복사·동기화는 없다.
LiveDepth에 응답 간격 필드를 추가했으므로 Small·native·VFG·RowFlow의 공유 구조
소비자를 모두 다시 빌드하고 해시를 갱신했다. 기존 coverage 바이너리는 보존했다.

## 비교 계약과 결과

검증 입력은 해시로 확인한 UVG-VCM의 FloorballGame, OfficeWalk, ParkingGarage
공개 1080p 프리뷰다. 각 3초/180프레임에서 매 두 번째 프레임을 처리하여
모델별·영상별 90프레임, 총 540프레임을 비교했다. 각 프레임의 동일한 FP16
추론 결과를 기존 DLL, 새 DLL의 비활성 정책, 새 정책에 입력했다. 시작·중간
강제 컷에서는 결과가 기존과 정확히 같아야 하며, 비활성 정책은 전체 구간에서
정규화/가이드 깊이/범위가 기존과 정확히 일치해야 한다. 모두 통과했다.
Small 공개 비교는 CPU cubic으로 raw depth를 source 크기로 복원한 후 동일한
GPU 후처리를 사용했다. 실제 Small GPU 복원과 네이티브 출력은 별도 동등성
검사로 확인했다.

시간축 지표는 별도 DIS MEDIUM 흐름으로 맞춘 광도 일치 영역의 깊이 차이를
1920px·강도 0.5의 연속 시차로 환산한 평균이다. 깊이 정답, 최종 SBS 픽셀
오차 또는 사람의 입체감 평가가 아니다. 경계 마스크는 기존 깊이 기준으로
두 후보에 공통 적용했다.

| 모델 / 영상 | 전체 오차 기존→적용 (px) | 감소 | 경계 오차 기존→적용 (px) |
|---|---:|---:|---:|
| Base / FloorballGame | 0.05535 → 0.04495 | 18.8% | 0.28950 → 0.28575 |
| Base / OfficeWalk | 0.22273 → 0.22198 | 0.34% | 0.40057 → 0.39488 |
| Base / ParkingGarage | 0.02892 → 0.02631 | 9.0% | 0.08262 → 0.08099 |
| Small / FloorballGame | 0.04820 → 0.03756 | 22.1% | 0.28155 → 0.27758 |
| Small / OfficeWalk | 0.21084 → 0.19958 | 5.34% | 0.43567 → 0.41900 |
| Small / ParkingGarage | 0.02941 → 0.02619 | 11.0% | 0.10340 → 0.10108 |

전체 절대 시차 P95 평균 변화는 모든 조합에서 1.5% 미만이다. 입체 강도를
크게 줄인 결과로 이 개선을 설명할 수는 없다. 다만 이 통계만으로 모든 물체의
정확한 깊이/입체감 보존을 보장하지 않는다. raw 값의 전체 변화를 보정하므로
‘범위 갱신만의 이동량’은 증가할 수 있다. 이것을 최종 일렁임 악화로 해석하면
안 되며, 위의 정렬된 전체 깊이와 함께 평가해야 한다.

단순히 범위 EMA만 느리게 만든 첫 후보는 Floorball 전체 오차가 약 7.9%
늘어 기본 적용하지 않았다. 회귀 보정 후에는 여섯 조합 모두 개선됐다.

## 합성·성능·출력 검사

- 고정된 중앙 물체를 두고 원근 끝부분만 진동시킨 GPU 검사에서 중앙 깊이
  표준편차는 Base 정책 0.004380→0.001898, Small 정책 0.007833→0.001628이었다.
- 순수 모델 배율/이동 변화를 가한 경우 정규화 깊이 최대 오차는 5.96e-8.
  컷은 새 인스턴스와 정확히 일치하고, 평탄 깊이도 유한한 결과를 유지했다.
- 신뢰할 RGB 표본이 없는 경우 30/60/120Hz에서 같은 0.5초 변화에 대한
  범위 반응은 1e-6 이내로 일치했다. 잘못된 간격/NaN은 거부한다.
- GPU 후처리 교대 측정: 6회 워밍업 후 21회 중앙값. 1080p는 기존 DLL
  1.214ms / 새 비활성 1.215ms / 적용 1.268ms, 4K는 4.619 / 4.619 / 4.686ms.
  정지 표본이 충분한 합성 입력의 source-depth 후처리만 측정했다. 모델 추론,
  캡처, SBS 합성 및 Qt 출력 FPS와는 별개다. 초기 직렬 추정의 약 3ms 추가
  비용은 병렬화로 약 0.054~0.067ms로 줄었다.
- CPU core/platform/profiles **238개 통과**. source-time 간격·컷·중복/역행·긴
  중단·잘못된 시각의 상태 보존 검사 포함.
- Small GPU 입력 27개 fixture와 4개 화면 크기(1080p/ultrawide/portrait/4K)의
  72개 SBS 사례에서 전처리·깊이·호스트/네이티브 출력 정확히 일치.
- Base/native/VFG 원본 6개 사례와 VFG 생성 2개 크기 검사 통과.
- 실제 Small/A/B Qt 실행: 기본 0.5, 새 `range` 정책 기록, 시작, 두 모니터
  이동, F11, 숨김/복원, 중지/재시작/닫기, 외부 캡처 허용 및 출력 재캡처 거부
  통과. 종료 후 live pools/nodes 0, 잔류 프레임 없음.

실제 Owl3D에서의 시청·눈의 편안함, 장시간 게임 안정성, 지속적인 4K 성능은
이번 검사의 결론이 아니다. 움직이는 물체의 지역적 깊이 오차와 가려진 영역은
남을 수 있다. 열려 있던 앱을 완전히 종료하고 다시 실행해야 새 모듈을 사용한다.
