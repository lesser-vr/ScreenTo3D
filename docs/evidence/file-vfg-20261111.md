# File depth strength and VFG — 2026-11-11

Behavior is owned by [PRODUCT](../PRODUCT.md#desktop-experience). This extends
the [file-queue evidence](file-queue-20261111.md); live VFG policies and artifacts
are unchanged.

## Changes

- The file workspace has a separate strength slider, reset and VFG 2x checkbox
  with help and the existing optional-model installation flow. Strength starts
  at 0.5; VFG starts off. Both are queue-snapshotted, are locked during work and
  do not change live settings. They are not saved across app launches.
- Strength scales file divergence without changing convergence, source geometry
  or model processing. The file API/CLI retain strength 1.0 and VFG-off defaults
  for backward-compatible diagnostics; desktop jobs pass their explicit values.
- `FileVfg` calls the existing pinned NVIDIA Medium 2x bridge using an owned CUDA
  stream and three pinned host/device RGBA buffers. Input is completed Full SBS;
  all four formats are packed after generation. It uses the existing SDK/model
  identities and does not load Torch or effects in the GUI process.
- `DoubleRate` keeps one owned previous stereo frame. For N source frames it
  emits N originals, N−1 intermediate slots and one final repeat, at 2× source
  FPS. Detected cuts fill their midpoint with the previous original instead of
  invoking interpolation. No generated image enters depth history. A single
  source frame produces two repeats; zero decoded frames remain a failure.
- SDK cleanup finishes before atomic output publication. Initialization,
  interpolation and cleanup failures cannot silently fall back or replace a
  previous output. Output FPS and source processing rate are reported separately.

## Reproduction and limits

In the prepared local environment:

```powershell
python scripts/test-contracts.py --group cpu --report out/new-contracts.json
python v1/test_desktop_file_queue.py --media-tools <ffmpeg-folder> --output <new-folder> --vfg
python v1/test_desktop_file_queue.py --media-tools <ffmpeg-folder> --output <new-folder> --vfg --model da2-small
python v1/test_desktop_file_queue.py --media-tools <ffmpeg-folder> --output <new-folder> --vfg --model vda-small
python v1/test_desktop_file_queue.py --media-tools <ffmpeg-folder> --output <new-folder> --vfg --model vda-small --offline
python v1/test_desktop_localization.py --output <new-folder>
```

The tests are short SDR/CFR clips on the prepared local GPU. They do not certify
long/4K exports, VFR timing, HDR color, other GPUs, clean-machine redistribution or
stereo/interpolation visual quality. Source-only oVDA uses the same post-synthesis
adapter but was not newly executed in this run. File VFG currently stages frames
through the host, so it is not a zero-copy or conversion-speed improvement claim.
Old portable packages are not automatically rebuilt by source changes.
