# Veyra 간헐 오류: 모의 재현 검토 (2026-11-18)

## 권장 방향

**테스트 전용 Python 입력 대체 → 실제 D3D11 모의 입력 창** 순서가 적합하다.
전자는 오류 처리·시간축 정책을 빠르게 검증하고, 후자는 실제 Windows Graphics
Capture/D3D11/CUDA/네이티브 출력 경로의 자원 교체를 시험한다. 앱 사용자 옵션이나
운영 경로의 자동 대체 기능으로 노출하지 않는다. 같은 날 구현과 반복 검증을 완료했다.
실행 방법과 결과는 아래에 기록했다.

## 현재 확보된 진단과 검증

현재 소스는 직전 최대 60초의 메타데이터를 약 1Hz로 수집하고 전환 이벤트를 추가한다.
오류 정리 전에 동결한 상태를 `data/logs/errors.jsonl`에 함께 남긴다. 작업 프로세스의
마지막 수락 입력·크기 변경·시각 역행·최대 간격과 Python 예외가 별도 공유 메모리로
남는다. 이 간격은 처리/출력 제한 때문에 생긴 대기도 포함하므로 독립적인 캡처카드
도착 간격으로 해석하지 않는다.

- CPU/Qt 회귀 검증 612개 통과, 생략 0.
- 실제 DA2 Small GPU 캡처/네이티브 출력으로 약 66초 실행 후 태그된 시험용 오류를 발생시켜 저장을 검증했다. 원래 Veyra 오류를 재현한 시험은 아니다.
- 직전 59.057초, 61개 상태, 기록 56,027바이트, 오류 전 native pool 1 → 정리 후 pool/node 0, 진단 수집 실패 0.
- 원본 창 제목은 저장되지 않았다. 영상·음성·키 입력은 기록하지 않는다. 로컬 원본 실행 경로와 코드 해시는 실행본 구분을 위해 저장한다.
- 과거 두 오류는 기록 도입 전 발생했고 실행본도 불확실하다. 모의 시험의 새 오류가 과거 두 오류와 같다고 단정할 수 없다.

## 1단계: 테스트 전용 입력/오류 대체

| 조건 | 대체 방법 | 판정/한계 |
|---|---|---|
| 일시적 프레임 부재 | 캡처 읽기가 100/250/500ms 동안 새 프레임 없음으로 응답한 뒤 정상 입력 재개 | 종료 없이 대기/회복, 정책에 맞는 깊이 이력 초기화. 실제 WGC/드라이버 동작 증거는 아님 |
| 시퀀스 건너뜀·시각 역행 | 원본 메타데이터의 sequence/time만 변경 | Small/Base/VDA의 명시된 시간축 정책과 예외 처리를 각각 확인 |
| 입력 크기 변경 | 유효한 프레임 크기를 640x360 → 1280x720 → 1920x1080으로 변경 | 크기별 자원 재생성/이력 초기화 검증. Python 가짜 버퍼만으로 실제 GPU 포인터 수명은 검증 불가 |
| 원본 닫힘·HWND/PID 재사용 | 선택한 창의 식별 정보/상태를 대체 | 의도된 안전 중지와 현재 오류 ID가 기록되고 정리되는지 확인 |
| 처리 예외·작업 프로세스 종료 | 정해진 예외를 내거나 소유한 시험 자식 프로세스를 종료 | 종료 코드·예외·직전 상태 기록과 비차단 회수 검증. 예외 주입 자체를 원래 버그 재현으로 인정하지 않음 |
| 출력/디스플레이 전환 알림 | 시험 소유 창의 전체 화면 및 가짜 화면 변경 이벤트 | 해당 제어 분기 검증. 실제 GPU 디스플레이 재구성/HDMI 신호 변경을 증명하지 않음 |

기존 캡처/시간축/네이티브 전달 단위 검증을 재사용한다. 테스트 실행기 내부의
의존성 주입으로 제한하고 실제 앱에 비밀 환경변수나 생산용 mock 분기를 추가하지
않는다. 각 조건은 정상 입력으로 시작하고 종료 후 정상 입력을 회복하는 구간을 둔다.

## 2단계: 실제 D3D11 모의 입력 창

가장 가치가 큰 통합 시험은 소유한 BGRA8/SDR D3D11 창을 실제로 렌더링하고 이를
평소처럼 캡처해 Small → GPU 입체 생성 → 네이티브 출력으로 연결하는 것이다.

1. 같은 HWND/PID를 유지한 채 60fps로 움직이는 패턴과 장면 번호를 표시한다.
2. `Present` 공급을 100/250/500ms 멈춘 뒤 재개한다. 실제 WGC 도착·합성 알림과 처리 수락 시각을 구분한다.
3. 입력 비율은 16:9로 고정하고 크기를 바꿔 `ResizeBuffers`와 캡처 표면 교체를 반복한다.
4. 같은 크기의 버퍼 재생성도 별도 시험해 해상도 변화 없는 표면 교체를 확인한다.
5. 입력은 고정한 상태에서 출력 창의 창/전체 화면 전환과 시작/정지를 각각 별도로 반복한다.
6. 각 회차 후 자원 수·진행 회복·새 오류 여부를 기록하고, 실패한 조건만 반복해 최소 재현으로 줄인다.

중간에 0 크기/숨김 창을 만들면 현재 정책상 안전 중지를 유발할 수 있다. 이를 유효한
지속 캡처 상태의 비정상 종료와 혼동하지 않는다. HDR/10비트나 모니터 제거는 SDR
기본군에서 분리한다. 모든 모의 창·프로세스는 시험 소유 범위만 닫고 사용자 게임,
Veyra, Owl3D 및 디스플레이 설정은 자동 변경하지 않는다.

## 재현으로 인정할 범위

- 정상으로 지원되는 상태 변화에서 예상치 못한 동일 오류 ID/HRESULT/스택이 반복되면 새 재현 케이스로 확보한다.
- 입력 부재가 정상 회복됐다는 결과와 화면 화질/지연/실제 사용자 게임 호환성은 별도다.
- 모의 D3D11 창도 Veyra 내부의 캡처카드 UVC/USB 처리, HDMI 재협상, 필터·출력 구현과 동일하지 않다. 모의군 통과 뒤에도 실제 Veyra 경로에서 확인해야 한다.
- 앱 GUI 자체의 네이티브 즉시 종료/전원 단절은 RAM 버퍼를 오류 이력에 내보낼 기회를 보장하지 않는다. 그 경우 기존 실행 로그·운영체제 오류 기록 또는 별도 덤프가 필요하다.

로컬 구현/검증 증거: `out/live-diagnostics-20261118/`의 회귀 결과와 `runtime2/`.

## 구현 및 반복 검증

Python 시험에서는 실제 SBS 작업 루프에 모의 프레임을 넣었다. 100·250·500ms
타임스탬프 간격, 프레임 부재, 시각 역행, 프레임 건너뜀과 크기 변경을 확인했다.
캡처 예외의 작업 프로세스 기록, 재사용된 창 핸들과 최소화 창의 거부, 모의
디스플레이 변경 알림에서 정리 전 상태 보존도 확인했다. CPU·Qt 검증 617개가
생략 없이 통과했다.

Windows에서 D3D11 시험 창을 빌드한 뒤 프로젝트 루트에서 실행한다.
프로젝트 Python과 DA2 Small 런타임·엔진 준비가 필요하다. 결과 경로는 새 폴더를 지정한다.

```powershell
./scripts/build-d3d11-live-source.ps1
./out/desktop-python/python.exe v1/test_d3d11_live_source.py --repeat 10 --output out/d3d11-live-source/repeat10
```

실제 D3D11 소스 → WGC → DA2 Small FP16 → 네이티브 Half Top-and-Bottom
출력(60 FPS 제한, VFG 끔)으로 다음 조건을 확인했다.

| 조건 | 횟수 | 관측 결과 |
|---|---:|---|
| 100·250·500ms 송출 정지 | 30 | 재개 뒤 새 입력과 SBS 제출 확인. 실제 Present 간격 101.8~117.6 / 251.8~269.4 / 510.2~516.4ms |
| 640×360 → 1280×720 → 1920×1080 → 640×360 | 30 | 새 출력 크기, 이력 초기화, 공유 텍스처 풀 세대 증가 확인 |
| 640×360에서 ResizeBuffers | 10 | 소스 버퍼 재생성 뒤 동일 크기에서 출력 재개 |
| 창 ↔ 전체 화면 | 20 | 모드 전환 뒤 새 프레임 제출 확인 |
| 정지 후 재시작 | 10 | 정지 시 풀·노드 0, 재시작 후 출력 확인 |
| 시험 원본 창 닫기 | 1 | E_CAPTURE_SOURCE_CLOSED, 자원 회수 |
| 시험 작업 프로세스 종료 | 1 | E_CAPTURE_STOPPED 및 종료 코드 -15 저장, 자원 회수 후 재시작 |

100ms 구간 10회 중 1회에서 공백에 따른 이력 초기화 카운터 증가가
관찰되지 않았다. 나머지 공백 구간 29회에서 초기화 카운터가 증가했다. 송출 간격과
ScreenTo3D가 받아 처리한 프레임의 간격은 다를 수 있다.

예기치 않은 오류는 0건이었다. 로컬 실행 결과와 시험용 오류 기록은
`out/d3d11-live-source/repeat10/` 아래에 저장했다. 실제 캡처카드, Veyra 내부
처리와 Owl3D 최종 표시 동작은 이 시험 범위에 포함되지 않았다. 과거 두 오류의
원인 확인에는 실제 사용 중 새로 수집한 진단 기록이 필요하다.
