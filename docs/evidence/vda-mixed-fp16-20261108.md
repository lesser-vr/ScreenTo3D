# VDA Small encoder mixed FP16

The Windows desktop v2 model pack uses FP16 in the encoder patch convolution and the QKV, output, FC1 and FC2 weight projections in each of twelve blocks. Inputs, projection results at their next FP32 consumer, attention score products, normalization, temporal modules, eight cache bindings and the depth head retain FP32. The two canvas sizes remain 518×896 and 518×924, each with warmup and cached graphs. Reproduce the conversion using `v1/build_vda_mixed_fp16.py` with the pinned original v1 ONNX pack and the TensorRT 11.2.1.2 runtime. The pack builder consumes the resulting graphs and the release reference arrays.

## Native output

Windows RTX 5090, VFG off, strength 0.5, full-resolution radius 12. The portable captured the owned public FloorballGame preview at 1080p and scaled 4K. The source advanced at approximately 62.5 FPS. Each engine ran in its own session, measuring three adjacent eight-second windows after five seconds of warmup at the default 60 FPS cap. FP32 ran first at 1080p and mixed FP16 first at 4K. ## Depth and stereo comparison

Both engines consumed identical source pixels with independent temporal and stereo histories. The sequence used 50 FloorballGame frames followed by a reset and 12 ParkingGarage frames at 1056×608 and 1920×1080, and 12 plus eight frames at 3840×2160. Runs alternated ordering each frame. All 144 paired outputs were finite. Worst frame mean absolute raw depth error was 0.0220% of the FP32 frame's P2–P98 depth range. In normalized aligned depth, worst frame mean absolute error at source Canny edges was 0.000082. The worst mean error in consecutive-frame aligned depth changes was 0.000036. These are pixel metrics rather than a physical display assessment.

Across those frames, mean absolute RGB difference in the full native SBS textures averaged 0.0156 on the 0–255 scale. Worst frame mean was 0.0434, and at most 0.179% of pixels in a frame differed by more than eight levels in any channel.

A second 144-frame comparison used the freshly installed v2 engines and the original signed v1 installation, switching the first clip to OfficeWalk. The maximum frame-mean raw depth error was 0.0566% of the frame depth range; the maximum frame-mean aligned temporal error was 0.000310. Native SBS mean absolute RGB error averaged 0.0306/255 and peaked at 0.0647/255. Up to 0.188% of a frame's pixels differed by more than eight levels in any channel.

## Installation and compatibility

The local v2 ZIP is 363,235,556 bytes. The installer rebuilt four engines from verified graphs and validated device identity, FP32 tensor contracts and finite outputs. Both final depth references remain the existing FP32 samples. Intermediate cache values change with precision: 3,186 of the 9,230 combined depth and cache reference samples exceeded the old FP32 comparison tolerance, all of them in the caches. The v2 pack therefore uses the validated mixed recipe's cache references, retaining the existing 0.001 absolute/relative tolerance. A fresh independent install passed this check at both widths.

The packaged native app then submitted 57.8 FPS at 1056×608 and 46.3 FPS at 4K in one eight-second smoke window each. Both packaged file modes produced 24-frame, 3840×1080 SBS files from a 1920×1080 fixture. The new revision has its own user/device-bound cache; both prior v1 FP32 profiles still passed verification with their original receipts. Raw quality, native, reference and install reports are in `out/vda-mixed-encoder-20261108/`. Physical viewing, long-duration thermal performance and other GPUs remain unmeasured.
