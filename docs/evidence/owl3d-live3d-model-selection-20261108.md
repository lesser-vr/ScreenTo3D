# Owl3D Live 3D의 224·518 깊이 모델 선택

Windows Blackwell 설치본 `screen_0.0.31/blackwell/Release/display-mirror.exe`에서 두 모델을 사용할 때, 크기에 따른 자동 선택은 **크롭의 가로와 세로가 각각 기준 가로와 세로의 40% 이하이면 224×224**, 한 축이라도 초과하면 518×518을 우선한다. 숫자는 깊이 추론에 넣는 정사각형 입력의 한 변 길이다. 하나의 Live 3D 세션에서도 크롭마다 모델이 달라질 수 있다.

## 선택 분기

아래 주소는 설치본의 RVA다. SHA-256은 `17b662fc80aa0aa918b80a714fe6e15256aebede64be3db42bb8b9127841e5f3`이다. 같은 설치본의 기존 REA PE import 증거 ID는 `ev_7679d5cb4b0ddd7d6977724f4adf6130a0e3495fd88de71c327e465e4ba0cba8`이다.

| RVA | 디스어셈블리에서 확인한 동작 |
|---|---|
| `0x0F4C31`, `0x3246BC` | 비교 상수는 단정밀도 `0.4f`이며 바이트는 `CD CC CC 3E`다. |
| `0x0F4C75–0x0F4CAC` | 크롭의 여섯 필드(+0x7C, +0x80, +0x9C, +0xA0, +0x8C, +0x90)가 모두 0이면 크기 비교를 건너뛰고 기본 슬롯을 쓴다. 여섯 필드의 제품 차원 의미는 확인하지 못했다. |
| `0x0F4CAE–0x0F4D16` | 크롭의 가로·세로(+0xD0, +0xD4)를 처리기에 저장된 기준 가로·세로(+0x30, +0x34)에 각각 비교한다. 가로 또는 세로가 40%를 초과하면 기본 슬롯, 두 축 모두 이하면 경량 슬롯을 우선한다. 이 분기에서 우선 슬롯이 비어 있으면 다른 슬롯을 시도한다. 기준 축 중 하나가 0이면 경량 슬롯부터 시도한다. 같은 비교가 `0x0E83AD` 부근에도 있다. |
| `0x0F4D21–0x0F4D4F`, `0x0F64EF–0x0F6525` | 선택한 모델의 크기를 직접 조회해 224·518을 구분하고 크롭에 기록한다. 이 태그는 각각 depth224·depth518로 집계된다. 별도 추론 그룹의 호출은 `0x0F508E`와 `0x0F5354`에 있다. |
| `0x09B1ED`, `0x06FDE5–0x06FE31` | 수동 모델 토글은 기본 슬롯 자체를 경량 모델로 바꿀 수 있다. 이 상태에서는 큰 크롭에도 224가 쓰인다. 전환 메시지에 표시된 단축키는 Shift + 백틱 + M이다. |

예를 들어 **선택기의 기준 크기가 2560×1440일 때** 1024×576은 두 축 모두 경계값이므로 224가 선택된다. 1024×577은 세로가 1픽셀 초과해 518이 선택된다. 이 예시는 두 모델이 준비된 기본 상태에서 크기 비교에 진입한 경우를 가정한다. 로그의 캡처 해상도만으로 선택기의 기준 크기를 확정할 수 없다.

## 실제 세션과 검증 범위

설치본 로그 `display-mirror_20261107_152913_34596_0000.log`의 244행에는 두 모델이 모두 준비됐다고 기록되어 있다. 414행의 첫 Live 3D 변환은 DEPTH224였고, 573행의 최종 누계는 총 3,250개 중 224가 458개, 518이 2,792개였다. 같은 설치본의 11월 6일 두 세션은 첫 변환도 518이었고 최종 224 누계는 모두 0이었다. 첫 변환의 전체 화면 플래그는 세 세션 모두 false였다.

40% 경계는 설치본의 네이티브 코드를 dumpbin으로 읽어 확인했다. 로그는 두 모델의 실제 사용을 확인해 주지만 개별 크롭의 치수와 선택 모델을 짝지어 기록하지 않는다. 경계 전후의 창 크기를 통제한 실시간 재현이나 단축키 조작은 이번 조사에서 수행하지 않았다. [앞선 설치본 식별 및 세션 기록](owl3d-live3d-gpu-20261107.md)
