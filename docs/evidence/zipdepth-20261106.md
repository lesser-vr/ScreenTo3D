# ZipDepth FP16 / native SBS experiment — 2026-11-06

## Decision

Keep ZipDepth as an explicit local comparison launcher, not a new default.
The model is fast and end-to-end native SBS works, but matched video depth
stability is worse than DA2 Small in these three clips. This does not meet the
user's main quality goal of reducing wobble. Higher input resolution or a different
temporal design remains a separate experiment, not something this result rejects.

## Conversion and adapter checks

The first official-export candidate failed parity: its export helper replaces
GlobalContextBlock's learned softmax-weighted context with average pooling.
Against unfused original FP32 on six public frames, depth-span-normalized MAE
after that export was 0.41–3.21%. Fusion alone remained effectively equal.
That candidate is retained at `out/zipdepth-20261106/prepare.json`, not installed.

Direct ONNX export of the fused original forward passed. CPU ONNX normalized MAE
was at most 0.000049%; TensorRT FP16 normalized MAE was 0.0478–0.1045%.
The predeclared gates were 0.01% for FP32 stages and 0.5% for FP16, plus finiteness.
Observed model-only timing was **0.868–0.935ms** at 704x384, ten warmups followed
by 100 forwards per sample. This excludes capture, preprocessing and SBS.
Evidence: `out/zipdepth-exact-20261106/prepare.json`.

Adapter reference tests at 1920x1080, 1000x1000, 720x1280 and 3440x1440 passed.
FP16 + GPU resize versus original FP32 + OpenCV preprocessing had normalized
MAE 0.095–0.600%, below the predeclared 1% adapter bound. The CPU and GPU uint8
bilinear paths are not bit-identical. Duplicate pending inference, expired token,
wrong-thread access and access after close were rejected.
Evidence: `out/zipdepth-adapter-validation.json`.

## Real 4K native output

Source: owned FloorballGame public video window. 3840x2160 input → 7680x2160 Full
SBS, Performance policy, strength 0.25, detail stabilization, VFG off, output
uncapped. Three ten-second measurement windows per model after startup.

| Source timer / condition | DA2 Small FP16 output FPS | ZipDepth FP16 output FPS |
|---|---:|---:|
| 16ms / ordinary public playback | 60.28–62.36 (median 62.19) | 62.27–62.49 (median 62.36) |
| 8ms / higher source-paint load | 30.60–30.80 (median 30.69) | 33.60–34.30 (median 33.70) |

FPS counts distinct native Qt afterFrameEnd IDs, not physical display refresh.
The 16ms source advances around 62.5 frames/s, so it limits the first comparison.
There is no evidence here for a large normal-playback FPS increase.
Raising the source update rate increased capture/paint contention and lowered
both outputs. The second row is **not the maximum FPS of either model**, nor
interchangeable with the first row. Its median improvement is about 9.8%.

In the 8ms condition, source-timestamp age P50 medians were 41.99ms (Small) and
40.60ms (ZipDepth); capture-callback age P50 medians were 47.20ms and 43.49ms.
Frame interval P95 medians were 40.88ms and 41.39ms respectively: improved mean
rate does not establish better tail pacing. Timing samples covered all distinct
submitted IDs in the measured intervals. WGC source and callback clocks have
different semantics; these figures are submission-age proxies, not photon latency.

Evidence:
- `out/zipdepth-native-4k/{runs.json,environment.json}`
- `out/zipdepth-small-native-4k/{runs.json,environment.json}`
- `out/zipdepth-latency-zipdepth.json`, `out/zipdepth-latency-small.json`

A zero-timer source stress attempt yielded about 19 FPS for ZipDepth. The matching
Small run stopped before completion (`SBS를 중지했습니다.`); the harness did not
retain a more specific initiating error, so no root cause or paired speed claim
is made. Both attempts remain under `out/zipdepth-native-max` and
`out/zipdepth-small-native-max`. This failure is outside the completed 16ms/8ms
comparisons and is not hidden as a successful maximum-rate test.

## Matched-frame quality

Three UVG-VCM public clips, 60 selected moving frames each (every second 60Hz frame,
30Hz source timestamps), followed by 12 repeated frames per clip/model.
Both models rendered actual 4K native SBS with independent histories and identical
strength 0.25 / Performance / detail settings. 432 total native renders completed.
This test uses prepared 1080p public previews enlarged to 4K; it does not establish
native-4K fine-detail accuracy. Output geometry and native processing are 4K.

Depth after motion correction was compared to the previous depth warped with
shared RGB DIS flow at 480x270. Cuts and unreliable photometric matches were
excluded. No depth ground truth exists. Lower residual alone can hide smoothing.

| Clip | Small mean residual | ZipDepth mean residual | Relative change |
|---|---:|---:|---:|
| FloorballGame | 0.002504 | 0.002622 | +4.7% |
| OfficeWalk | 0.011289 | 0.020656 | +83.0% |
| ParkingGarage | 0.001120 | 0.001451 | +29.6% |

Moving-region residuals also worsen: about +4.9%, +82.1%, +51.0% respectively.
Depth spans remain broadly similar. Gradient averages are lower for ZipDepth in
Floorball/Parking but higher in Office: no blanket claim of better edges follows.
Static-tail drift is also larger for ZipDepth in Office/Parking.

Two saved OfficeWalk depth frames were visually inspected. At frame 58, Small
separates bottle/chair boundaries more cleanly; ZipDepth has diffuse boundaries
and more surface texture variation. This is a still-image observation, not
normal-speed video or binocular acceptance.

Evidence: `out/zipdepth-quality-4k-v2/report.json` and saved source-named SBS/depth
PNGs. The first diagnostic harness forgot to consume unsaved native slots and
failed with a keyed-mutex timeout; v2 consumes every slot, including static probes.
That was a diagnostic harness ownership bug; the ordinary native GUI consumer
was not changed to bypass synchronization.

## Operation and limits

`Run-Compare-ZipDepth.cmd` starts the explicit Owl3D-compatible trial. Select a
source window, then start SBS. Default strength 0.25, VFG disabled. The output is
an independent root window and is intentionally capturable, using the existing
comparison launcher's verified affinity and recursion protection. Other app
windows retain exclusion. Normal launch privacy/defaults are unchanged.

Actual GUI checks passed: 1920x1080, 960x960, 3840x2160 sessions, start/stop/restart,
output hide/show recovery, correct Full SBS dimensions, zero native pools/nodes
after each stop, no reported app errors. First square probe used 1000 logical
conversion at 150% DPI and rounded to a different physical size; the corrected
960 square avoids that harness rounding ambiguity. Evidence:
`out/zipdepth-launch-smoke.json`. Platform contracts: **98 passed**;
`out/zipdepth-platform-tests.json`. Python compilation passed.

No actual Owl3D binocular/comfort review, long-session qualification, other GPU
support, VFG integration or portable distribution approval is claimed.
The source/weight licensing questions remain in the prior review; local execution
does not resolve commercial redistribution scope. App and owned test windows
were closed after validation. No commit or push was performed.
