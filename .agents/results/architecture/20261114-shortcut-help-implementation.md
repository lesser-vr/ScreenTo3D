# 조작·단축키 안내 구현 결과

- 날짜: 2026-11-14
- 구현: 메인 실시간 3D 헤더의 ? 및 실시간 출력 설정 상단 ‘조작·단축키 안내’에서 같은 안내를 연다. 파일 변환 헤더에는 추가하지 않았다.
- 전역 키와 출력 로컬 키의 범위를 두 그룹으로 분리했다. 앱 창의 크기를 바꾸지 않는 비모달 QML Item 팝업으로, 좁은 창에서는 본문만 스크롤한다. 제목/닫기는 고정하고 스크롤바 공간과 긴 영어 문구의 줄바꿈을 확보했다. 재개방은 맨 위로 돌아간다.
- 키보드 Space/Enter 활성화, Escape 닫기, 바깥 클릭 닫기와 안내 버튼으로의 포커스 복귀를 제공한다. 한국어/영어 언어 변경은 즉시 적용한다.
- 단축키의 표시 문자열·Win32 ID·키·수정키를 shortcut_keys.py에서 관리한다. 메뉴와 안내는 이 정의를 사용한다. 등록 실패 행에는 상태와 대체 버튼을 표시한다. 준비 완료 후 메인 상태에 6초 안내를 세션/실패 키별 1회 표시한다. 오류창이나 재생 오버레이를 새로 열지 않는다.
- 반복되는 상태 통계에서는 안내 모델을 갱신하지 않는다. 기존 네이티브 출력과 원본 포커스 정책은 변경하지 않는다.

## 검증

- 전체 CPU: 637개 중 636개 통과, 기존 symlink 권한 테스트 1개 skip (`out/shortcut-help-cpu-final.log`). 새 안내 정책 테스트 7개 포함.
- 실제 QML: 한국어/영어 각각 380x260 및 420x260에서 경계·스크롤·원래 창 크기 유지·키보드 열기/닫기·바깥 클릭·재개방 초기 위치를 확인했다. 설정 진입과 두 단축키 충돌 상태, 실제 생성된 대체 버튼 클릭도 통과했다. `out/shortcut-help-20261114/ui-verified/report.json`.
- 실제 앱 소유 이미지에서 한국어/영어 키/설명, 좁은 폭의 줄바꿈, 스크롤바 여백과 고정 제목/닫기를 시각 점검했다. 안내 시뮬레이션은 등록 상태/재생 대상을 고정했고 외부 앱에 전역 입력을 보내거나 캡처/추론을 실행하지 않았다.
