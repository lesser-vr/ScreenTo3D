# 3D 표시와 원본 입력 포커스 분리 검토

- 날짜: 2026-11-14
- 상태: 아래는 당시 권장 설계안이다. 승인 후 1차 구현과 자동 검증을 완료했다. 최신 결과와 실제 기기 수용 범위는 [구현 기록](../bugs/bug-20261114-output-focus.md)을 참조한다.
- 사용자 요구: 3D 화면은 계속 보면서 원본 창에서 키보드뿐 아니라 마우스 클릭·드래그도 해야 함. 조작할 때마다 원본/3D 창 포커스를 왕복하는 동작 제거. 기본 화면의 옵션 노출은 최소화.
- 이 조작 흐름의 UX 평가: 6/10, 최고 심각도 3(주요). 원본으로 전환할 때 출력 전면 상태를 다시 확보해야 하는 문제(-2), 출력 관리를 위해 입력 포커스를 다시 빼앗아야 하는 문제(-2)를 개선 대상으로 평가했다. 앱 전체 점수는 아니다. 10/10 목표 조건은 입력·표시 분리, 모든 필수 출력 제어의 접근성, 정상 탈출/오류 처리, 실제 Owl3D 및 마우스 드래그 검증이다.

## 현재 코드에서 확인한 점

- Main.qml의 sbsOutput은 일반 Window이며 표시 순서 유지/비활성 입력 정책이 선언돼 있지 않다.
- showOutput은 showNormal/showFullScreen을 호출하며 원본 입력 대상에 대한 포커스 복귀 정책이 없다.
- F11/Esc와 출력 메뉴는 출력 창의 로컬 입력에 의존한다. VFG Ctrl+Alt+S는 이미 Windows 전역 단축키다.
- 커서 캡처는 기본 True이고, 네이티브 WGC 세션의 IsCursorCaptureEnabled로 전달된다. 실제 3D 화면의 커서 가시성/쌍상과 조작 정확도는 별도 확인해야 한다.
- 창 선택 캡처와 모니터 캡처의 외부 캡처 허용/피드백 방지 정책, 독립 출력 창 소유 관계는 포커스 개선과 별도로 유지해야 한다.

## 권장 1차 범위

출력 창을 보기 위한 창으로 만들고 실제 조작은 원본 창이 직접 받게 한다.

1. 출력이 입력 포커스와 무관하게 보이도록 표시 순서를 유지한다. 일반 직접 출력은 TopMost + NoActivate 조합이 후보이며, Owl3D의 최종 mirror/overlay가 있을 때는 그 최종 3D 화면 위를 중간 SBS 창이 덮지 않도록 순서를 검증해야 한다. 모든 최상단 창 위로 매번 raise하는 방식은 사용하지 않는다.
2. 3D 출력 노출/전체화면 전환이 키보드 포커스를 가져가지 않게 한다. 첫 프레임 준비 후 원본을 활성화하는 동작은 명시적 시작 직후와 검증된 창 선택에 한해 1회 시도한다. 사용자가 이미 다른 앱을 조작하고 있으면 포커스를 빼앗지 않는다. Windows의 SetForegroundWindow 제한을 우회하거나 반복 호출하지 않는다.
3. 키보드와 마우스 클릭·드래그는 원본의 정상 입력 경로를 유지한다. 외부 모니터에서 3D를 보더라도 마우스는 원본 화면/창에서 조작하고, 캡처된 원본 커서를 3D 화면에서 보는 흐름을 우선 검증한다. 원본을 클릭한 뒤 3D 창으로 돌아올 필요가 없는 것이 핵심이다.
4. 출력이 포커스를 받지 않아도 전체화면/창 모드를 바꿀 수 있도록 메인 설정에서 접근 경로를 제공하고, 전역 단축키 후보 Ctrl+Alt+Enter를 검토한다. 게임이 쓰는 F11/Esc를 전역으로 가로채지 않는다. VFG Ctrl+Alt+S는 유지한다. 등록 충돌은 기존처럼 설명하고 메인 창 제어를 남긴다.
5. 평소 새로운 버튼/스위치를 기본 화면에 늘리지 않는다. 창 위치/크기 조절처럼 출력 창을 직접 관리해야 할 때는 제한된 관리 동작을 제공하고, 종료 시 원본 조작 상태로 복귀한다. 오류창과 정상 중지 기능은 고정 출력에 가려지지 않아야 한다.

이 방향은 원본 창에서 마우스를 사용하는 경우에도 포커스 왕복을 제거한다. 3D 모니터 위의 좌표로 다른 모니터의 원본을 직접 클릭하는 기능까지 포함하는 것은 아니다.

## 마우스 관련 대안

| 방식 | 해결하는 범위 | 판단 |
|---|---|---|
| 원본 입력 유지 + 출력 비활성/표시 순서 유지 | 기존 키보드·마우스·게임패드 조작, 출력 재선택 제거 | 우선 권장 |
| 마우스 클릭 통과 | 같은 화면의 해당 좌표 아래 창으로 입력 전달 | 겹침 배치에서만 별도 검토. 다른 화면의 선택 창으로 보내는 기능이 아님 |
| 3D 화면 클릭을 원본 좌표로 중계 | 다른 화면의 3D 뷰를 직접 클릭/드래그 | 후속 기능. 배율·여백·각 눈 포장·시차·Owl3D 변환을 고려해야 함 |

직접 중계는 절대 좌표만 비례 변환해서는 정확도를 보장할 수 없다. Half/Full SBS/TB, 모니터 DPI, 표시 여백과 창 크기, 시차에 따른 오브젝트 위치 차이를 함께 고려해야 한다. 드래그 중 button-down/up 짝 유지, 휠/우클릭, 원본 이동/닫기, 상대 마우스 입력 앱도 별도 검증이 필요하다. 캡처카드의 영상 창은 실제 게임 입력 대상과 다를 수도 있으므로 캡처 HWND를 무조건 입력 대상으로 취급하지 않는다. 이번 기본 포커스 문제 해결에 저수준 입력 주입을 먼저 추가하는 것은 권장하지 않는다.

## 구현 후보와 주의점

- Qt WindowStaysOnTopHint / WindowDoesNotAcceptFocus 및 Windows WS_EX_NOACTIVATE, SWP_NOACTIVATE가 기본 후보다. 기본 창 플래그는 최초 표시 전에 적용해 네이티브 핸들·그래픽 자원을 불필요하게 다시 만들지 않게 한다.
- WindowDoesNotAcceptFocus는 Windows에서 출력의 별도 작업 표시줄 항목에 영향을 줄 수 있다. 메인 ScreenTo3D 제어 창/아이콘은 계속 접근 가능해야 한다.
- WindowTransparentForInput는 NoActivate와 다른 기능이다. 기본으로 섞지 않으며, 켜면 기존 우클릭 출력 메뉴 접근이 사라질 수 있으므로 관리/탈출 수단을 먼저 마련해야 한다.
- 원본이 창 캡처이면 검증된 HWND/PID를 사용할 수 있지만, 모니터 캡처에는 입력 대상 창이 하나로 정해져 있지 않다. 자동으로 임의의 창을 활성화하지 않는다.
- 포커스/표시 순서 변경은 시작·상태 전환 시 처리한다. 매 프레임 전면 고정·포커스 확인/탈취 폴링을 추가하지 않는다.
- Owl3D가 활성화된 경우 실제 전면 창과 포커스 소유자가 ScreenTo3D인지 Owl3D인지 런타임 확인이 필요하다. 외부 앱의 창을 임의로 수정하지 않는다.

## 수용 조건

- 원본 클릭·드래그·키보드 입력 중 3D가 계속 보이고, 3D 출력에 다시 포커스를 줄 필요가 없다.
- 명시적 시작 후 준비 완료 시의 포커스 처리, 다른 앱 사용 중 늦은 준비 완료, 전체화면 전환/복원, 원본 창 이동·크기 변경·닫기를 확인한다.
- 원본 커서가 3D에서 보이는지, 클릭 위치와 드래그 결과를 판단할 수 있는지, 물리 커서와 캡처 커서가 혼동되지 않는지 확인한다.
- VFG 전환과 원본 입력이 유지되고, 전체화면·중지·출력 관리·오류창에 포커스 없이도 접근 가능하다.
- 실제 Owl3D 모드에서 중간 SBS가 최종 3D 화면을 덮거나 사라지는 회귀가 없다.
- 최근 개선된 표시 주기와 GPU/CPU 사용을 다시 측정한다. 출력 모드 전환 중 그래픽 풀/노드가 남지 않아야 한다.
